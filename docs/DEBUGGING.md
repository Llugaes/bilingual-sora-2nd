# 诊断与回归约定

此页是排版、漏译和原生钩子的维护入口。具体布局合同见 [ARCHITECTURE.md](ARCHITECTURE.md)，命令入口以 `tools/dev.py` 为准。

## 先取得能复现原症状的证据

1. 记录候选组件摘要、游戏版本、游戏来源语言、主副语言、控件路径、首次进入或热切换。截图说明症状，实际控件原串说明输入；两者都保留。
2. 在修改前运行能判失败的检查。字号问题比较同一字符跨格式段的字形尺寸；位置问题比较首次进入和切换后的同一控件；漏译问题把实际完整原串交给正式解析器。
3. 引擎回调顺序、字段和子上下文必须来自对应版本机器码或运行态证据，测试不能自己发明这些行为。
4. 修复后按原入口与断言重跑，记录实际覆盖和未覆盖的范围。Python/JS 对齐、隐藏原生主机和游戏画面分别报告。

## 原生钩子与富文本

- 先比对磁盘指令、实际进程指令和分支目标。Frida 会跟随挂载地址上的跳转，传入地址不一定是实际拦截地址。
- `tests/check_native_size_hook.py` 执行真实形状的字号分支、公共出口和颜色分支。旧安装方式必须复现累乘，生产安装函数必须只影响字号分支。直接调用缩放函数的单元测试无法替代它。
- 颜色开、闭标记分别核对入口；有的入口会跳过公共出口前几条指令。颜色、粗体、图标、原生注音与绝对字号分别覆盖。
- 引擎的 `<C>` 不创建子注音对象；嵌套 `<R>` 从固定注音字号创建新的对象。这两个过程不可用同一个虚构模拟代替。
- 生命周期需要覆盖首次赋值、延后字体赋值、布局结束和热切换；不能靠某一页面的固定坐标补偿修正整类问题。
- 驻留代码变更只在新游戏进程加载。当前场景用 `tools/read_native_layout.py` 只读采集；不通过再次附加 Frida 来试错。

## 漏译与动态文本

1. 从实际原串反查资源身份，区分未提取、语言缺项、歧义冲突、动态组装和原生接管遗漏。
2. 目录缺项时检查原始资源及同类型全族；不要把字幕截图逐条补进词典。
3. 动态格式按真实参数合同扩展。范围大小、效果程度、属性名、数值和百分号是不同参数域；不把所有 `%s` 与所有词条做笛卡尔积。
4. 详情专用短词只在已验证的详情上下文生效，保留全局歧义隔离。用相邻不适用输入验证不会误译。
5. 对合法资源组合跑全部支持语言，并检查 Python 与实际 JS 解析器一致。`tests/check_reported_texts.py` 使用完整目录，不能只用删去了同文冲突的精简词库。报表分开列出完整配对、缺项、歧义和未覆盖资源；测试数量不等于覆盖率。
6. 单个调用实例不等于指令的完整参数合同。固定偏移或过滤条件新增后，扫描被排除的同族输入并分类；合法的可选元数据不能被当成译文缺失。全屏说明使用 `tools.audit_static_panels` 核对原始八语资源与重建后的目录。

## 2026-09-27 纠正

字号分支尾部的跳转被 Frida 追踪到了公共命令出口，使颜色开始标记也执行副文倍率。此前“颜色产生继承子对象”的解释与机器码不符，相关模拟测试虽通过却漏掉真实故障。现改用独立分支入口安装和实际机器码回归；实机采集另行记录，不能由隐藏主机通过推断游戏已验收。

全屏说明 command 8 的首字符串位置会变化。固定 arg4 会漏掉 arg3 变体；但任意整数前缀也不能忽略，`17,itemId` 会在首字符串之前生成道具名。当前只提取已确认的窗口／单样式前缀和静态正文，复杂前缀保留为未确认。西语详情中的“单体”则与技能名存在同文异译，精简词库缺少这个冲突，因此必须增加完整目录回放，并仅在详情范围内使用范围标签的身份。

跨项目经验保存在外脑的 `native-hook-branch-redirection` 事件卡；本页保留项目命令与合同，外脑不复制本机路径和运行地址。
