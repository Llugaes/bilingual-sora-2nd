# 诊断与回归约定

此页是排版、漏译和原生钩子的维护入口。具体布局合同见 [ARCHITECTURE.md](ARCHITECTURE.md)，命令入口以 `tools/dev.py` 为准。

## 先取得能复现原症状的证据

1. 记录候选组件摘要、游戏版本、游戏来源语言、主副语言、控件路径、首次进入或热切换。截图说明症状，实际控件原串说明输入；两者都保留。
2. 在修改前运行能判失败的检查。字号问题比较同一字符跨格式段的字形尺寸；位置问题比较首次进入和切换后的同一控件；漏译问题把实际完整原串交给正式解析器。
3. 引擎回调顺序、字段和子上下文必须来自对应版本机器码或运行态证据，测试不能自己发明这些行为。
4. 修复后按原入口与断言重跑，记录实际覆盖和未覆盖的范围。Python/JS 对齐、隐藏原生主机和游戏画面分别报告。

## 首次安装与准备性能

首次安装的问题必须从空状态验证：没有 `native-status.json`、语言缓存和已保存游戏目录，不能用开发机热缓存证明新用户可用。分别记录目录解析、模型编译、字体准备和游戏连接耗时；把构建前移不能写成构建提速。Steam 的安装语言与游戏内部文字语言可能不同，不能据此伪造检测结果。首次字体准备必须自动进行，不要求目录、来源语言或开始准备操作；映射允许在首次连接后初始化，不能把映射完成作为启动游戏的前置条件。测试需证明空状态自动发现并安装字体、不会提前猜测来源编译映射，且不读取旧版手动选择。并发准备验证使用独立进程及实际文件锁，覆盖旧任务结果隔离、字体失败不误报就绪、准备期间启动游戏时不写字体。开发测试不得启动、附加或改写真实游戏。

## 原生钩子与富文本

- Node 测试不能证明 Frida 内嵌 V8 支持同样的语法；`tests/check_runtime_text_engine.py` 在自建隐藏进程中加载完整生产解析器，核对脚本可加载及回路标签／数字边界，不附加游戏。
- 先比对磁盘指令、实际进程指令和分支目标。Frida 会跟随挂载地址上的跳转，传入地址不一定是实际拦截地址。
- `tests/check_native_size_hook.py` 执行真实形状的字号分支、公共出口和颜色分支。旧安装方式必须复现累乘，生产安装函数必须只影响字号分支。直接调用缩放函数的单元测试无法替代它。
- 颜色开、闭标记分别核对入口；有的入口会跳过公共出口前几条指令。颜色、粗体、图标、原生注音与绝对字号分别覆盖。
- 引擎的 `<C>` 不创建子注音对象；嵌套 `<R>` 从固定注音字号创建新的对象。这两个过程不可用同一个虚构模拟代替。
- 生命周期需要覆盖首次赋值、延后字体赋值、布局结束和热切换；不能靠某一页面的固定坐标补偿修正整类问题。
- 普通注音从 `ruby_begin` 建立范围；独立副文直到 `ruby_base_measure_return` 才能根据结束标记识别所属层。两条入口都须在字形游标回退时清理前次排版，不能只依赖 `count===0`。重复重建测试必须包含未接管的装饰线／数字／图标前缀、多层、真实换行封口，同时比较主副文字号、颜色和位置；同一帧再次布局必须保持不变。
- 驻留代码变更只在新游戏进程加载。当前场景用 `tools/read_native_layout.py` 只读采集；不通过再次附加 Frida 来试错。
- 原生 R 注解的测量与绘制分别核对：主文原注解高度 a、副文原注解高度 a′ 独立增加本行上方空间，首行也适用；同一行多个注解取该层最大高度。没有相应注解时该项为零。副文内的原注解继续继承副文倍率。不能用“保留原始行位置”的旧断言覆盖这项要求，也不能只移动字形而让日志测量仍返回旧行高。测量许可只授予已登记的双语临时上下文，并关闭字形输出；普通单语言注解的权限不变。
- 区分字形的实际 scale 与绝对字号命令所需的相对倍率。S/s 写入的是请求字号除以标签字体基准，R 的初始值则来自固定注音字号；不能把 R 的实际 scale 再直接乘到 S/s 结果上。`tests/check_native_size_metrics.py --exe ...` 执行真实字号取表／除字体基准指令，并调用生产登记和修正方法。回归必须包含字体基准不等于控件字号的组合；仅用两者相等的宿主会掩盖反向缩小。嵌套 R 仍使用自身实际 scale，不能被绝对字号倍率覆盖。

## 漏译与动态文本

1. 从实际原串反查资源身份，区分未提取、语言缺项、歧义冲突、动态组装和原生接管遗漏。
2. 目录缺项时检查原始资源及同类型全族；不要把字幕截图逐条补进词典。
3. 动态格式按真实参数合同扩展。范围大小、效果程度、属性名、数值和百分号是不同参数域；不把所有 `%s` 与所有词条做笛卡尔积。
4. 详情专用短词只在已验证的详情上下文生效，保留全局歧义隔离。用相邻不适用输入验证不会误译。
5. 对合法资源组合跑全部支持语言，并检查 Python 与实际 JS 解析器一致。`tests/check_reported_texts.py` 使用完整目录，不能只用删去了同文冲突的精简词库。报表分开列出完整配对、缺项、歧义和未覆盖资源；测试数量不等于覆盖率。
6. 单个调用实例不等于指令的完整参数合同。固定偏移或过滤条件新增后，扫描被排除的同族输入并分类；合法的可选元数据不能被当成译文缺失。全屏说明使用 `tools.audit_static_panels` 核对原始八语资源与重建后的目录。
7. 全量审计的分母来自原始 PAC 文件、脚本调用和表字段，不能来自提取器已接受的目录。运行 `tools.audit_resource_inventory`，保留全部拒绝项、未知 schema、动态操作和语言缺项；标识符、开发标签、重复记录不能直接统计成屏幕漏译。`tests/check_reported_texts.py --panel-audit ...` 再把所有静态面板交给正式 JS 解析器，完整保留全局匹配失败；有编译身份的结果另列，不能代替日志丢失身份时的结果。
8. 表资源身份排除本地化后移动的地址，但必须保留实际非显示资源串和条件数组内容。先验证字段类型、长度和八语身份集合，再提取显示字段；空数组指针可能恰好指向相邻文本，不能因为地址能解码为 UTF-8 就认定它是漏掉的文本字段。
9. 日志实际输入可能携带运行时的 `<#...>` 表情头，与脚本字面量不同。完整精确匹配失败后保留这个头，先以整段正文查找，再考虑拆行。不要用截图中的裸句通过代替实际原串通过；`<K>` 等正文控制不能顺手删除。回放必须继续到 `render(..., 'annotation')`，核对最终注音或独立副文层；主副语言各自 `translate` 成功仍可能被注解资格检查漏掉。
10. 图标／控制标记独占一行时，该行没有可挂副文的文字容量。重排行映射必须保持原行位置和样式状态，不能先分走下一句的字符再因为找不到注解锚点而丢弃。
11. 动态正文从静态提取器排除后，必须有独立的 producer 编译入口。BP、休息金额、食谱解锁、静态 ITEM_ADD 调用分别按实际操作码和物品 ID 域生成；颜色中的数字不经过通用名称替换。`dynamic-audit.json` 保留原始调用分母和拒绝原因。某一语种同名冲突或缺失不能删除其他语言可用的整条记录。
12. 技能详情由多个效果记录组装，不能只验证单条 name/format。按原始 parameter_types 和已验证的槽位检查 LINK、共享概率、回合数、强度及无参数属性组：磁盘 `SkillParam` 从 `+0x30` 开始五个 16-byte 槽，原始 `ItemTableData` 从 `+0x6c` 开始三个槽，不能共用错误的布局。审计脚本也必须由原始机器码／资源建立边界，不能仅复用生产提取器的槽位常量。组合只在已知详情正文锚点中使用。已知 stat 字段边界的尾空格可用于等价比较，不能把整段内部空白或真正的措辞差异删掉。
13. 保存后的历史记录未必有本次连接捕获的脚本身份。说话人只能缩小完整对白候选；仍有同角色异译时继续保留歧义。显示与隐藏行高测量必须使用同一记录来源，并验证全部分段、owner、代次及原始内容，不从当前场景猜测旧对白。
14. `<#...>` 表情头会被运行时改写，不能拿完整头的字面命中解除正文歧义。模型的 `pairs` 准入表与解析器必须一致；原生来源捕获则不能以当前配对是否冲突为开关。用同正文、同说话人、不同表情头且不同译文的资源回归；旧历史保留与新调用身份还原分别断言。
15. 单行动态通知中的颜色和图标不能作为独立副文排版边界。完成整句参数替换后，核对 `render` 输出的所有副文内容、数值、图标和层数；仅比较 `translate` 的结果无法发现食谱前缀与名称重叠。`tests/check_dynamic_and_history.py` 从原始动态家族生成输入，真实冲突单列，不能计成已翻译。
16. 身份捕获、日志保存和控件继承都必须独立于当前目标语言。回归应先在无局部 resolver 的语言模型下生成记录，随后切换到同文异译的语言，检查当前可见行、重新打开的行、隐藏行高测量及双语副文。只向解析器手工传入一个正确 ID，证明不了前面的 ID 曾被捕获。`tests/check_history_identity.py --game-dir ...` 用真实资源调用验证跨语言 ID；`tests/profile_native_hash.py --native` 在自建隐藏宿主验证 native pointer 输入，不能以 Uint8Array 模拟通过代替原生哈希路径。

17. 对白记录以独立的脚本调用 ID 为主键，禁止用任意首条／最常见译文填补同角色同文异译。测试必须先产生两条独立调用、写入日志，再切换语言；不能只测试手工传入正确 ID 的翻译器。字节码调用顺序与元数据可能因嵌套调用不同，局部同一 ordinal 不能证明 PC 映射。参数身份可唯一定位记录时保留该独立 ID，不能因当前译文相同合并记录。
18. 冷解析性能用完整资源模型和第一次出现的完整详情串测量，热缓存命中不能代表打开页面的耗时。新增组合规则前量化规则数量和每次渲染的匹配次数；不能通过删掉已证明合法但当前表中未实例化的组合改善性能。候选索引仍须保留所有可能匹配与冲突，不能变成首条命中。
19. 游戏文字语言切换后，日志可同时保留多种来源语言。已捕获记录用稳定调用键、实际来源语言及完整原串，不能拿当前脚本摘要解释旧语言的记录。连接前的旧记录只能以全部来源语言中的完整正文与已保存说话人做唯一解析；姓名也从旧记录读取。`tests/check_mixed_history.py` 回放真实八语旧正文、日英目标及最终副文；同文冲突不能由当前语言的全局配对覆盖。历史索引只在已验证的日志显示／测量入口使用，不向普通菜单扩散。

20. 一处语言元数据差异不能静默排除整个函数或任务。局部对齐必须保留真实调用 ID，并验证调用顺序与可选参数的原生缺省语义；不能删除非零说话人、语音或控制差异。任务覆盖的分母包括跨场景的完整函数族和任务表，不只是一张截图或单个函数。参数类型、效果记录类型与原生 switch 枚举是不同数据层，只有验证生产者到消费分支的字段链后才能建立组装合同。偏移必须注明进制和记录基址；不同 native 指针的同名字段不能直接套用到 PAC 记录。

21. “现场漏译而离线通过”先核实进程实际加载的模型、驻留代码与完整原串，再区分资源解析和控件生命周期。MessageLog 的 row-ID 命中可能只激活旧 controller；测试真实激活边界，并单独比较首次打开、关闭重开、重复打开的正文、副文、row bounds、字号与换行。文字恢复但行高或字形漂移仍是失败。控件复用校验不能只比较槽位和正文；相同字节也可能属于另一个独立 call ID，缺少来源的旧记录也要核对完整原始 stamp。

22. UI 增加的前置 S/s 字号指令不属于资源文本身份。保留指令，仅在剩余整段有确定配对时解析完整富文本，避免颜色边界拆散带参数的确认句；不要枚举字号值，也不能删除原生 R 注音来获得命中。地图目的地、任务委托方即使中文同名也可能有不同的官方译法，资源族限定与真实控件入口必须分别验证。

23. 进程内 sidecar 缺失不等于旧日志完全没有原生身份。先核对 ring 保存字段及 builder → writer 的机器码传递，再按原始调用分母建立可恢复索引。控制指令和它的参数须按真实消费起点与参数宽度区分，不能扫整数值就认定消息 ID。正、负／哨兵值及动态 speaker 都要单列；同一调用的跨语言版本不能误计为多调用冲突。`tests/check_history_marker.py --game-dir ...` 保留原始分母；显示、隐藏测量、分段一致性、完整 stamp 与读档后的最终 render 另有生命周期回归。

24. 日志整体偏移在实际投影边界验证，不在重复 Update 中累加局部坐标。姓名与正文共用偏移，底部余量不足时同量限幅；空姓名、正文未翻译、销毁／复用、冷热双语切换均须覆盖。矩阵在 Update 返回后恢复，原生行框、子节点位置、单语与主动语音不改变。

25. 动态标题的回归必须包含“标题＋图标参数＋换行＋完整说明”。回路仅关联“X 属性”和“属性值”两个标签，不复制整行、括号、图标或数量；单图标和多图标使用同一模板上下文，不枚举图标组合。标签在完整词库中存在跨领域冲突，必须同时检查独立标题、已知说明及未知后缀。`tests/check_quartz_labels.py` 用完整目录回放主副语言和渲染结果，`tests/check_reported_texts.py` 保留跨功能检查。全角 `＋` 与半角 `+`、原生图标与纯数字分别保留，不能用便于通过的替代输入代替问题输入。

26. 已替换的生产者片段不再经过通用词典；只递归处理未匹配的间隙，避免完整词库把参数数字二次解释为别的文本（如 `2→２`）。原始五槽展开后，第四／第五个效果不能使前面已合法的“无参数前缀＋两个相邻回合属性”失效；不相关效果插在前缀和属性之间时仍拒绝。保留完整词库回放与这两种相邻边界回归。

27. 发布遗漏和运行时遗漏分开核对。候选组件摘要不是 Git commit；以正式包的 installed-manifest、实际文件摘要和对应 tag 确認交付内容。完整词库中能翻译裸标签，不能证明实际控件准入、来源身份和缓存正确。`t_text.tbl` 同时存在 native key 与直接字符串指针入口，后者也须按 `TextTableData` 的稳定文本键接入身份解析；保留“同文不同 ID 不同译文”的回归，不能用全局同文覆盖来修复按钮。

## 2026-09-27 纠正

字号分支尾部的跳转被 Frida 追踪到了公共命令出口，使颜色开始标记也执行副文倍率。此前“颜色产生继承子对象”的解释与机器码不符，相关模拟测试虽通过却漏掉真实故障。现改用独立分支入口安装和实际机器码回归；实机采集另行记录，不能由隐藏主机通过推断游戏已验收。

全屏说明 command 8 的首字符串位置会变化；窗口标记可连续出现，也可位于正文中。原始家族审计发现旧单样式前缀漏掉416条静态说明。当前按实际公共 builder 和 command-8 callback 的操作码合同读取完整正文，保留控制流作为配对身份。`17,itemId`、数值插值和未解析变量仍不能被忽略。普通对白的 speaker 参数与其后的动态正文前缀也必须区分。西语详情中的“单体”则与技能名存在同文异译，精简词库缺少这个冲突，因此必须增加完整目录回放，并仅在详情范围内使用范围标签的身份。

相同说明的译文只有行首／行尾居中空格不同时，可从完整配对中选取一条原始译文；比较不删除词内空格、标点或换行。真实措辞不同仍须通过资源身份区分，不准按最常见译文或任意首条解除冲突。

跨项目经验保存在外脑的 `native-hook-branch-redirection` 事件卡；本页保留项目命令与合同，外脑不复制本机路径和运行地址。

带分隔线的日志发生逐帧缩小，与此前字号钩子误入颜色分支是两条不同路径。前者因独立副文入口没有退休上一帧的范围，非零前缀绕过了零字形清理。旧回调回放中主文字形 17→14.45、副文 11.9→10.115；修正后连续重排稳定。分隔线不需要删去，也不能只修正文从第零个字形开始的情况。
