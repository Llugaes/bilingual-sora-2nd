# 工程结构与契约

这个仓库只负责《空之轨迹 the 2nd》。其他游戏可以建立同命名系列仓库；在第二个真实接入需求出现之前，不引入通用游戏插件框架或工厂层。

## 模块职责

| 目录 | 职责 | 不承担的工作 |
|---|---|---|
| sora_bilingual/app | Qt 界面、展示状态、自动连接调度 | 游戏文本解析、资源下载 |
| sora_bilingual/game | 受版本约束的 Frida 接入、原生脚本、后台生命周期 | UI 控件、网络更新 |
| sora_bilingual/localization | 本地资源解析、身份映射、文本编译、索引缓存 | Qt、进程附加、网络 |
| sora_bilingual/config | 语言元数据、配置规范化、显示动作策略 | 资源扫描、视图创建 |
| sora_bilingual/platform | Windows 进程与输入、SDL 手柄、跨进程文件锁 | 游戏翻译业务 |
| sora_bilingual/fonts | 本机字库合并、校验和可恢复安装 | 分发游戏字库 |
| sora_bilingual/updates | GitHub 协议、后台检查、安装事务、本地热更新 | Qt、游戏钩子 |
| tools | 构建、验证、诊断 | 运行时依赖 |
| tests | 单元、契约、故障恢复和独立进程验证 | 自动启动游戏 |

launch.py 是稳定桌面入口，bootstrap.py 是组装入口：先恢复未完成的安装，再导入 Qt 应用。模块层级依赖由 tests/test_architecture.py 检查；运行代码不能反向导入开发工具。早期 overlay 的兼容测试实现归档在 legacy，不进入发行包。

## 状态和副作用

- `connection_activity` 统一计算连接按钮、状态徽标和阶段卡片；过期心跳不能表示仍在连接，后端常驻也不等于连接未完成。已确认游戏退出时取消连接中展示。字体／映射准备使用黄色，连接阶段使用蓝色，就绪使用绿色，错误使用红色，均同时显示标题与说明，进行中使用不定进度提示。字体状态独立于连接状态。

- paths.py 是安装根目录与持久化目录的唯一定位入口。进程以模块方式启动，并明确设置工作目录；不依赖调用者当前目录或固定 Steam 盘符。
- 所有用户状态保存在 generated/；安装清单只管理明确拥有的程序文件。目录重构不移动配置、字体安装记录或索引缓存。
- ActionPolicy 按选定模式处理同一个 switch_binding 的按下、按住和松开。Hold / Toggle 输出主或副语言单语；annotation 使用本游戏的原生注音能力。旧 hotkeys 仅作迁移来源，运行时不再同时监听三个动作。原生后端是“当前已生效模式”的事实来源。
- `platform/gamepad_labels.py` 负责 SDL 设备映射到按键名称的转换。设置页发现设备时读取并缓存同一 pygame SDL 的类型与映射，录制时将 `profile` 元数据随原始绑定保存；后端轮询不查询这份元数据。`label_style` 只决定显示名称，触发仍使用原始 GUID、按钮、轴方向与阈值。Nintendo 面键在设备边界统一为位置语义，单只 Joy-Con 的横／竖握和成对模式分别命名；名称表不假设设备原始轴号。
- “语言”页只放 MOD 配置，启用开关在首位，主副语言用两列；界面语言归入“工具外观”，更新使用独立的标题栏入口。关闭的下拉框忽略滚轮，展开列表仍可滚动。
- `apply_startup_language` 以 EXE 路径、PID、创建时间记录游戏会话；每个新进程按实际检测的文字语言同步主语言一次。相同进程重连不覆盖手动选择，检测期间用户改动也保留；副语言只在首次无配置时应用默认值。
- ui_language 与游戏语言独立。app/i18n.py 保存中英日界面文本，app/ui_widgets.py 保留 Qt 控件的源文案并在语言改变时重新翻译；不改动游戏文本模型。app/presentation.py 只把状态转换成可显示内容，不创建 Qt 对象、不访问文件。
- 资源缓存的语言依赖只包含档案名称映射，界面名称和默认偏好不参与失效判断。编译器代码及游戏资源变化仍使缓存失效；旧索引必须匹配资源和旧解析器指纹才能迁移。模型构建复用全局配对结果，缓存通过 C JSON 编码器原子写入。
- 磁盘模型校验区分原始配对与去格式配对：`pairs` 的译文必须完整非空，`plain_pairs` 可因纯格式控制规范化为空字符串，不能因此整份失效并在每次启动重建。`tests/test_cache_io.py` 用正式编译器输出和三个独立进程验证后续启动不重新加载资源；本机完整缓存基准见 [后续启动检查](verification/warm-cache-loading.md)。
- 冷构建逐文件复用字节完全相同的语言脚本，最多 4 个 spawn 工作进程处理独立批次；父进程按原顺序收集有界结果并独占写缓存，错误诊断和缺失语言仍逐语言保留。小目录使用串行路径。`tests/check_startup_performance.py` 可在不启动游戏的情况下比较完整索引哈希、冷／热缓存耗时与 EXE 校验耗时。EXE 校验仅解析所需 PE 头和节表，完整文件哈希及重叠特征匹配校验保留。
- 历史 marker 编译只重读目录中含精确物理调用候选的脚本／函数／调用，不能把其他语言候选或冲突过滤掉。2026-09-28 的只读冷构建基准中，每语待重读脚本从 1,082 降至 198；模型阶段 85.208→51.525 秒，总计 173.771→142.728 秒，热模型 1.446 秒。完整目录摘要和同进程旧／新完整模型字段均相同；这是本机资源基准，不代表新电脑实测。
- 静态对白在完整有序调用、命令、说话人及语音身份一致时，允许纯字符串分段和换行差异；分段不同只配对整句，不配对参数片段。完整对白／说话人显示记录的唯一配对优先于未配对的脚本片段，实际译文冲突仍隔离。ActiveVoice 身份包含说话人、条件和语音数组的内容，排除字符串池地址变化。
- 运行态日志中的 `<#...>` 表情头不一定等于资源中的字面值。全串无精确配对时保留头，对完整 display 正文重新匹配，之后才进入分段回退；不删除 `<K>` 等正文控制，不解除真实同文异译冲突。
- 全屏 command 8 按原生 builder 合同消费字符串、换行、语音编号和可重复的窗口标记；静态资格不再依赖首字符串固定位置。动态插值仍单列。完整译文只有每行边缘填充空格不同时允许选取一条原始配对，词内空格、换行、标点及真正措辞冲突不合并。
- 地图跳转点、调查点、场景查看器地图、名称、状态和提示表的身份保留已验证的非显示资源串或条件数组内容，排除地址本身。重复标量 ID 不足以唯一定位资源；同 kind 的多个 section 继续保留 occurrence。Tips 的数组计数是 uint32，紧邻的打包标量不能当指针抹去；空数组指针可指向相邻文本，不能据此新增文本字段。
- 有序的成就、主动语音、姓名及前作任务历史由 `table_alignment.py` 保留独立记录位置，并以非文本结构序列校验跨语对应；主动语音以会话组隔离。帮助条目按主题和标题／图标起始行分组，续行不增加条目序号，分页和列宽不作为身份。完整字段先按段落对应，只有同分段数的语言追加单行配对。目录保存 `table_rows` 物理来源，表指针模型复用该来源；审计逐行对照原字节，并将仅有完整段落覆盖的字段单列。它们是表资源定位键，不是脚本对白 ID。检查见 `docs/verification/ordered-table-identity.md`。
- 注解模式统一用于菜单、对话、回顾与过场字幕；旧内部 bilingual 值兼容为 annotation。新增注解沿主文实测左缘显示，原文自带注音和强调点保留原位置。关闭详情只收起设置，状态条显隐由用户的隐藏／打开操作控制，不随游戏焦点变化自动隐藏。
- 完整调用结构不能对齐时，另行核对完整对白子序列、原调用位置、总调用数及说话人／语音身份；无关 UI 或奖励参数格式不再否决已验证的对白。该路径只导出完整对白，不放宽其他参数片段匹配。
- 道具／技能详情中的范围后缀、效果程度来自独立资源。`item_help_components()` 按已验证的稳定资源身份，组合圆形范围 label 与四种尺寸、HP 回复 name 与五种程度，生成完整精确配对；目标顺序使用对应语言的模板。身份屏蔽本地化指针、保留 native 类型字段，在八语资源中一致。不能将全部 `%s` 字段与程度做笛卡尔积：属性追击的 name 接收属性，format 常接收数值或状态，short_label 也不一定允许尺寸。上述未验证类型不生成配对，数值格式沿用原有处理。不会把任意相邻词拆开翻译，缺语言及同文异译仍进入既有拒绝规则。
- HP／EP 百分比与全回复由 stat、format、PERSENT／ALL 以及可选 SELF／FRIEND 组装。单属性 builder 保留日韩中与西文的顺序及韩文空格；五槽原始技能记录又证明同参数 HP／EP 的 LINK 聚合，完整头模板防止英文 `Recover 25% HP/EP` 被斜线拆开。不同参数及其他效果类型不能由这个合同推断覆盖。无参数文字标签只在详情上下文生效，格式骨架和标点不作独立译文。
- 注解资格比较折叠全角 ASCII 并忽略显示控制，但保留原生 `</R读音>` 内实际可见的注解内容；同一 Latin 正文的不同读音也需要副文。完整配对以解析出的主副语言生成排版，原始输入独有的注解或等待标记不能迫使注解模式返回原文。纯图标和等价数字不新增标记。混合未翻译文字的标签保留原生文字推进、基线及行距；仅缩放已确认双语范围内的字形，按图标分段，保留段落左缘和底边。等级、时间、难度及图标的字形不动，原始字形矩阵随排版缓存，避免逐字显示时重复缩小。普通注音和独立注解统一在原生解析完成、世界坐标转换之前，用各自字形矩形的边缘计算间距；排除按钮图标，计入文字阴影。只移动 Mod 新增的副语言字形，原文注音和强调点不动。间距以本地排版坐标计量，屏幕缩放和字形留白仍可能影响视觉间隔。
- ConnectionPolicy 按 PID 和进程创建时间去重。界面与后端为不同进程；收起／隐藏不影响连接，托盘“退出工具”则停用效果并等待界面、后端和准备进程全部结束。成功确认前不隐藏托盘。UI 代码热重载使用独立的界面交接入口，不发送退出工具请求。
- 悬浮条单击与拖拽共用 `DragSurface`，按系统拖动阈值二选一。悬浮条 —、设置窗口 × 与系统关闭事件均只隐藏到托盘；Esc/齿轮收起设置。真正退出只从托盘进入既有安全停用流程。位置、背景透明度保存在 `overlay-window.ini`；旧 Pin 值不再控制界面。背景保留一个 alpha 阶用于 Windows 点击命中，前景保持不透明。
- 游戏内脚本安装后 eternalize，由游戏持有其钩子与回调；退出工具仅 disable 和断开控制端，不卸载正在使用的跳板。原文由既有 UI Update 恢复，隐藏控件在再次显示前恢复。工具重开经 IPv4 loopback 控制通道复用同一脚本，单所有者、随机令牌鉴权、长度有界帧；所有者断线也停用效果。端点按游戏 PID、创建时间和 EXE 绑定，当前游戏端点无法连接时拒绝重复安装钩子；协议不兼容要求下次正常启动游戏。源代码摘要不一致会提示底层更新尚待新游戏进程，不把重连当成已更新。
- `tool_shutdown` 的退出请求独立于用户配置；UI 同时检查后端操作系统锁与 PID／创建时间，后台处理结束后才消失。模型和字体准备通过顶层 `preparation_worker` 组合各模块，工作器在启动子进程前加入 Windows Job Object；取消或工作器退出时，其所有后代一并结束，不包含游戏进程。字体最终安装事务等待完成后再退出。
- 首次安装自动发现游戏并准备字体：目录发现覆盖 Steam 用户／机器注册表、默认安装目录及 libraryfolders。界面只显示字体状态，无目录、来源语言或开始准备表单。字体就绪即可启动游戏；首次语言映射在连接后按实际检测的来源自动构建。只有同安装目录上次已确认的来源可用于后台预热，不读取旧版 `preparation-choice.json`，也不伪造检测状态或修改游戏设置。
- UI 预构建和首次后端编译共用 `model-preparation.lock` 的操作系统文件锁；获得锁后重新检查缓存，进程退出自动释放。该锁不等同于后端驻留锁，不附加游戏。并发打开游戏不会重复编译同一份目录和模型；自动发现的安装目录或语言组合变化后，过时结果不能覆盖当前准备状态。
- ModelPreparation 负责异步编译、丢弃过时结果；相同组合的在途请求去重，代码更新强制重建不能被后续普通请求取消。编译器在短期工作进程中运行；准备结果只回传缓存路径和覆盖统计，已连接的驻留脚本直接读取经过摘要校验的打包缓存，避免 Python 再读完整模型。旧版调用保留分块事务兼容，应用失败保持旧索引。
- 原生字号不在已验证的字号指令范围内时，沿用游戏排版并缩放已确认归属的双语字形，不注入推测的字号，也不因单个控件停用连接。正常运行不逐条传送文本诊断；状态仅累计身份匹配、翻译与字形排版耗时，逐条文本只在诊断开启时记录。
- 书籍的主副文显式行数不一致时，纯文本按主文有效行容量分配完整副文，优先保留段落边界、Latin 单词和句末标点。主文换行、空行不变；已验证的颜色、字号、粗体、图标、原生注音标记按原子片段处理，样式跨行时闭合并重新打开，主文控制字节不变；未知或不完整标记保留原文。
- 副文重排对纯图标／控制行保留零文字容量，只传递样式状态，不消耗随后文字行的译文。最后一个有容量的主文行接收剩余副文，后续纯控制行不会导致尾部文字丢失。
- GitHubClient 封装网络和协议校验；UpdateService 只负责策略与后台调度；update_installer 负责包验证、互斥锁、备份和恢复日志。测试通过客户端替身和临时安装根目录验证同一个接口，不需要公网或游戏。

## 更新协议

发行包格式为协议 1：ZIP 加 SHA-256 清单。安装时只接受根目录程序文件、sora_bilingual/ 中的 Python/JavaScript 和图标资源；拒绝路径穿越、Windows 保留名、链接和本地文件冲突。

安装先获得后端互斥锁，再写备份与 prepared 日志，原子替换程序文件，最后记录 committed 并发布热加载清单。未提交中断恢复旧文件；已提交中断补完热加载清单。运行中不替换 Python 依赖或游戏 DLL。

发布文件由 release-files.json 明确列出。架构测试验证完整运行时已列入、开发工具与本地状态未列入。GitHub Actions 只有带版本标签、测试通过的提交能发布；全部资源先传到草稿，随后公开。版本一致性同时检查标签、distribution.json 与 pyproject.toml。

## 扩展方式

- 新增语言：维护语言元数据和资源规则，不在 UI 或渲染器中添加语言对专用分支。
- 新增文本表：扩展结构解析与身份对齐，补最小合成输入和跨语言回放，不用截图 OCR 兜底替换。
- 支持新游戏 EXE：新增并验证版本契约，再修改原生接入；不放宽现有摘要门槛。
- 新增界面选项：先定义配置含义和后端确认方式，再接入视图。不得让 UI 提前宣称尚未应用的状态。
- 新增更新格式：同步客户端验证、构建器与中断恢复测试；不能只修改打包脚本。

## 多语言字体交付

游戏文字使用自己的 FNT 和 BC7 字形图集，不依赖 Windows 安装的字体。AutoConnector 在独立后台任务中从本机各语言 PAC 生成字形并集，保持各源语言已有字形；不分发游戏资源。发行包内含经过摘要校验的 MIT 资源加载器。游戏未运行时按原流程安装；已经运行时通过游戏自己的资源加载入口准备独立字库和贴图，完成后在 Update 切换整个 font face，无需修改游戏目录或晚加载 DLL。映射和字体都就绪后才显示双语。运行时字体方案的验证层级见 [runtime-fonts.md](verification/runtime-fonts.md)。

生成物按游戏目录和源资源指纹缓存，安装前校验 FNT、DDS、SHA-256 和游戏版本契约；解压后图集不得超过已验证的 32 MiB 原生缓冲区。界面与后端使用 platform/file_lock.py 的同一个字体构建锁，等待后重新检查缓存；进程被结束时 OS 释放锁。安装记录按游戏目录隔离，内容完全一致的旧文件可以收养；未知的加载器或其他 MOD 字体不覆盖。写入失败恢复原文件。UI 单独显示准备、游戏内加载、冲突或失败状态，尚未完成加载不能显示双语已就绪。

运行时清单包含四个字库家族的源 FNT 摘要，按实际 face 内容识别，不依赖用户选择的语言。已有对应并集字库时直接复用；否则从已校验缓存加载新 FNT 和独立名称的 DDS。图片文件读取只在 image-cache 的已验证 CALL 位置接入 C 回调，原有全局文件读取器（含资源加载器的跳转）保持不变。字库来源在游戏 Update 中取得；文件读取、哈希和贴图创建在独立事件循环中执行。准备完成后以单个指针切换完整 face，旧资源保持存活；更新 font generation，使未翻译的原文也重建字形，下一帧不重复刷新。退出工具在下一次 Update 恢复原 face；游戏 reset 前恢复引擎原本拥有的对象，新 face 保留在有界缓存中供重新启用复用。原生模块更新仍只在新游戏进程安装，不能把首次字体免重启误写成旧驻留脚本可热卸载。

## Windows 便携发行

`tools/build_portable.py` 在构建端校验官方 CPython 压缩包，安装固定版本的 wheel，保留许可证，再调用文件白名单打包器。用户端不运行 pip。`BilingualSora2nd.exe` 是短生命周期 GUI 启动器，读取 `runtime/current.txt` 并启动对应内置 Python；不依赖 PATH。

发行环境仅保留应用使用的 Qt Core、Gui、Widgets、Network 绑定及窗口、样式、图片、网络插件，并通过 PE 普通和延迟导入递归保留其 DLL 依赖。软件 OpenGL 回退、VC 运行库与许可证保留；QML、Qt 开发工具和 pygame 示例、测试、文档正文不进入发行包。新增 Qt 模块时同步构建根集合；测试检查应用导入以及成品图标、SVG、样式、TLS 和 SDL 输入初始化。ZIP 使用标准 Deflate 压缩，Windows 资源管理器即可解压。GitHub 附件直接展示 `bilingual-sora-2nd-<version>-windows-x64.zip` 文件名，使用说明放在发布正文。

运行环境目录使用内容摘要作为标识，不可原地修改。同一环境的文件更新时跳过，新依赖写入新目录；旧环境保留，界面重载通过 EXE 选择新环境。更新日志仅备份有变化的文件，配置与缓存仍在 generated。首次运行打开设置；后续双击复用常驻实例。

CI 在无游戏环境运行提取后 EXE：清除 PATH 中的 Python，测试含空格/中文路径、全部依赖导入、隐藏恢复、真实 UI 热重载和单实例。

## 组件更新与安装器

更新清单保留协议 1 的完整 ZIP 描述以兼容 0.3.0–0.3.3，新增可选 `components`：程序包包含完整安装清单及除 `runtime/<id>/` 外的文件；依赖包只包含该目录。新客户端在依赖标识相同时逐文件验证本地依赖并复用，只下载程序组件；标识变化或不可复用时获取依赖组件。组件分别校验来源、文件名、大小、SHA-256，组合后继续使用同一安装事务、互斥锁和回滚。跨版本升级无需补丁链。已验证的下载缓存可以复用。新客户端不认识未来的协议或更新失败时，界面提供安装器／完整包入口和恢复步骤，底层异常只进入日志。

这是程序与依赖分离，不是二进制差分。完整 ZIP 始终提供；0.2.2 的 501 文件上限无法由服务端修改，需要手动迁移。不要移除旧客户端依赖的完整包与 schema 1 字段。

## 连接预缓存与布局生命周期（0.3.9）

等待游戏期间，AutoConnector 从已验证的历史路径或 Steam 库发现安装位置，在独立工作进程中准备当前语言组合。相同任务只构建一次，连接等待该任务完成；有效缓存不会再次编译。修改字号、间距不重建语言模型。

model_wire.py 将完整模型无损编码为共享节点，使用来源大小、修改时间与格式版本确定缓存身份，并校验内容摘要。V8 从本机文件读取，验证所有引用、键与节点后才提交新解析器；读取失败保留旧状态并回退有界 RPC 传输。共享节点作为只读模型，解析器缓存另存。缓存不进入发布包。tests/check_cached_connection.py 仅附加自己创建的隐藏测试进程，记录预热后的读取、EXE 校验、附加、模型展开及构造耗时，不启动或附加游戏。

原生 SetText 后仍会发生字号和排版标记赋值；每个已追踪标签记录生成注解时的字号以及动画、禁用注音标记（`flags & 0x0c`），更新回调发现变化时重排一次。这使图鉴首次进入与模式切换使用相同的最终标记，也使晚绑定的动画对白进入独立注解路径。暂停标记不作为失效条件，避免暂停时重置逐字显示。没有变化时不重复调用 SetText。只改间距等几何参数时，也会标记原生测量和绘制失效，避免只在调整主字号后才生效。动画对话重排使用游戏自己的文本初始化入口重置旧解析游标，保留已显示比例；已暂停的对话仅临时解除绘制暂停位以更新当前句。

游戏部分调用方会内联文本写入，绕过 SetText。公共测量入口在同一个游戏回调中识别这类写入并完成替换；递归写入按线程和控件隔离，未改变的文本不重复处理。读档角色名单无需按姓名或语言硬编码。

原生禁用注音的 `flag 8` 必须在测量阶段保留，仅绘制 Mod 拥有的副文时临时解除并恢复。真实 Frida 在回调内部调用 NativeFunction 时不会再次触发嵌套的 Interceptor：若首次外部测量清除该标记，热切换内部测量却保留它，同一文本就会得到不同高度，继而产生不同的垂直居中位置。自建隐藏进程的 `tests/check_native_reentry.py` 运行正式权限回调和对应原生分支模型，覆盖这两条真实回调路径；Node 合约模拟不能代替此检查。该检查不执行游戏自身渲染器，实机仍须比较首次进入与热切换后的测量高度、行注音标记及字形坐标。

测量阶段同样必须保留原生一次性注音高度补偿，无论正文是否混排图标、数字或独立副文层。底部详情曾在两条路径得到 84 / 96 的测量下界，使 73 个字形整体相差 6 个布局单位；字号、图标尺寸、父级矩阵与文本均相同。按 `reserveRubyHeight` 分类抑制测量补偿会漏掉混排控件；现在该抑制仅作用于绘制阶段。测量时的副字号缩放、独立层锚点处理及额外行距仍保留。

Update 回调内修改文本后，不能把嵌套 setter 的测量结果当成最终结果。实际文本变化、重放以及仅几何变化统一在回调末尾置原生测量／绘制脏标记；回调返回后，由同一次原生 Update 按 measure → draw 顺序执行完整回调。这使首次排版与热刷新共享测量路径，也覆盖此前只有几何刷新才触发正式重测的遗漏。稳定帧不置脏；动画先恢复显示比例，再正式测量，暂停位在绘制后恢复。内联写入和复制构造本就会继续执行外层正式测量，不额外插入刷新。单元模拟检查模式／字号／标记变化，独立 Frida 宿主检查嵌套回调抑制、正式重测次数和动画暂停状态；这些不能替代新游戏进程的最终坐标对比。

字形范围直接从实际绘制过程记录：普通注音在 `<R>` 开始处记录正文起点，在注音绘制前后记录副语言范围；独立注解先绘制空锚点上的副语言，再绘制正文，按这一实际顺序记录。关闭标签处的正文调用只是重新测量，不能作为正文绘制起点。每次重新排版或模式切换都会废弃旧范围，未改变的帧复用结果。姓名与混合排版保留限定的原点修正；普通正文不自动全局上移。用户可用 `bilingual_offset_y`（默认 0，正值向下）平移双语标签的最终字形，保持主副语言相对间距；单语言不应用这一偏移。

原生标签复制构造会跳过 SetText，直接复制模板的 UTF-8，再立即测量。受版本指纹保护的复制入口在首次测量前继承已追踪模板的原文与资源身份，并按当前模式和字号重新生成独立排版状态；不反向解析双语结果，不共享字形范围或副语言缓冲区。源模板和目标文本必须与已记录结果完全一致，才允许继承。

道具列表的 `item_template/name` 控件使用道具名称表限定匹配范围，避免与地图菜单等同名资源混淆；同一道具范围内的译文冲突仍不猜测。DLC 身份保留物品编号、数量数组的长度与内容，排除随本地化字符串池变化的数组地址；越界数据拒绝解析。

已知边界：统一间距不改变游戏固定背景的高度；窄标题条可能容不下当前字号和新增注解。本轮不引入按控件名称匹配的偏移表，也不自动缩小用户字号。


## 源语言检测与段落上下文

连接前以只读脚本读取已验证游戏版本的文本表，至少三个独立键一致才接受原文语言；初始化中未就绪时等待并退避重试，不将未知值作为用户配置。手动重试沿用 AutoConnector 的进程身份和驻留连接去重，不能卸载或替换正在运行的 native hooks。

任务进度正文由游戏先拼接完整记录再逐行 SetText。quest builder 的版本指纹限制了捕获入口、完整缓冲位置和行 setter 返回地址；上下文按线程与同步调用栈存活，并要求原始行严格按序一致。RuntimeParagraphs 只在完整缓冲的行边界精确匹配已配对的多行记录，以原行索引分配译文；完整上下文缺失、顺序改变或最长记录存在歧义时走普通文本路径。不会按孤立短句猜测任务。原生复制与模式切换保留原始段落身份。

动画对白使用独立注解层，读取原生解析器已经显示的主文字符进度，按各行进度逐渐显示副语言；不把标记字节、阴影或副语言字形算作主文进度，不改写游戏的逐字显示时钟。副语言的 RGB 系数作用于每次排版保存的原颜色，透明度为原 alpha × `secondary_opacity`（默认 0.9）× 当前行显现进度，文字、图标与阴影一起生效，重复刷新不累乘。主语言的颜色、透明度、数字与图标尺寸保留原样。

日志控件会每帧重新解析部分文本。首个双语片段前可能存在未翻译前缀，因此不能仅靠字形数量归零判断新一轮解析；同一解析器的片段起点回退时废弃上一轮片段与颜色缓存。未改变的帧复用结果，不累计过期片段。

简单静态 ruby 的字形对齐与着色由 `native_geometry.js` 中的 CModule 批量执行。原生 `0x40` 每帧重建保持不变；每次解析后传入本次字形数组、片段索引与样式，同一次解析不重复调整，不跨解析持有字形指针。C 函数在写入前校验全部将读取的字段，只写拥有的坐标与副文 RGBA；主文及未归属字形的颜色不参与副文颜色校验。代码随驻留组件在新游戏进程中编译，不能热替换。采用 JS 源文件承载 C 字符串，使旧版更新器仍可校验安装包。

动画、混排缩放和独立注解层保留脚本路径：块读取本次涉及的字形，缩放、边界、间距和颜色计算复用同一份数据，只写回拥有的尺寸、坐标及 RGBA 字段，不回写整个原生结构。同一原生回调内的注解辅助步骤复用一次文本所有权检查，下一回调仍重新校验，不能跨原生写入缓存。Windows 上的 `tools.dev check` 在自建隐藏进程中执行真实 Frida CModule 与正式脚本函数的差分、越界保护和解析生命周期检查，不附加游戏。

状态计时区分原生测量、最外层绘制解析、全部几何调整及其 C 批处理子阶段；测量与解析统计包含它们内部的脚本回调，不能与所有细项简单相加。离线速度改善不能代替实际日志打开耗时与帧率验收。已在旧候选实机复现单语约 160 FPS、双语约 85 FPS，后处理占主要额外耗时；新进程已验证静态几何批处理后双语日志约 120–140 FPS；图鉴 14 个同指针控件的首次/热切换测量与字形坐标一致，用户也已确认。日志打开仍约 700ms，实测双语 3,015 次测量耗时 484ms，单语 3,013 次耗时 85ms；该阶段与持续绘制分别优化。

副语言中的图标继续使用游戏原生图标绘制。游戏的注音解析器只复制普通字形回调，未复制独立的图标回调；独立注解在绘制阶段通过经过版本校验的原生 clone 入口，将图标回调复制到子解析器自己的存储区，交给游戏原有清理流程释放。测量阶段不复制，主语言回调不改变，也不借用父回调的生命周期。

逻辑热更新只替换纯文本解析工厂。加载前拒绝含有原生插桩 API 的代码，防止开发诊断绕过驻留组件的重启边界；此检查用于防止误操作，不是 JavaScript 安全沙箱。新增或修改原生测量点必须随驻留脚本在新游戏进程中加载，不能在运行中的游戏里反复追加临时 hooks。

日志打开的临时测量限定在版本校验的 `0x362BD0` 循环，不能泛化为跳过 SetText。游戏先克隆可见行，再复用隐藏模板计算历史记录的 descriptor；最终行绑定走另一条路径。模式 1 的语音列表固定高度为 148，无需执行两次模板测量。模式 0 保存已验证的标量行高（最多 4,096 条、8 MiB 键预算），并单独保存最多 256 个名字的行高贡献；第一次遇到正文仍由游戏精确测量，重复打开可复用行高。命中只写当前 descriptor，保留 ID、当前窗口宽度、循环和临时字符串析构，不改 label 的 glyph count、line-info、bounds 或字符串，也不跨行持有原生对象。

缓存键包含正式解析器得到的完整 wanted 文本、独立副文层、字号/宽度/字体等测量字段。预览使用独立的 JS 行对象，不登记控件或分配副文缓冲；miss 仍走正式 setter，并对比实际文本、层内容和布局策略后才发布结果。键同时包含主字号比例、副字号比例和额外行距；单纯配置 epoch（颜色、透明度、整体偏移或切回既有语言）不清空已验证行高，当前解析结果不同时自然未命中。字体 reset/load 仍清空全部结果；测量中途发生 epoch 改变时不发布该次结果。关闭普通布局不会误清字体缓存。名字命中时，使用 float32 运算复现原生 descriptor 高度公式，正文继续原生测量。该优化不能把首次出现的全部正文测量成本视为已消除，实机须分别记录首次及重复打开。

测量分支使用版本校验的单条 8 字节指令入口及附近分支页，不通过写 `Interceptor.context.rip` 假定跳转成功。分支页先在原生层将 selector 清零，再执行回调，最后恢复被替换的 RBX 加载；原路径、整行命中、固定高度、仅姓名命中四个继续点均保留游戏循环和析构。页面与 listener 随驻留脚本存活，只能在新游戏进程安装。设备相关图标不进入行高缓存。`tests/check_native_log_measure.py --exe <sora_2nd.exe>` 在自建隐藏宿主中运行实际原生函数副本，验证机器码分支、翻译 setter、原生高度逐位一致、析构和失效条件；通用检查不要求安装游戏。


高频 `parse_text` listener 由 `native_parser.js` 的 CModule 执行。普通 outer/nested parse 不进入 JavaScript；独立注解的 parent Map 保留为身份和比例的权威源，注册时将 pointer、generation、placement 镜像到原生有界表，parse 返回后按同一代次清理两侧。短锁内不调用 JS；1024 项耗尽后本进程永久退回完整 JS Map 查询，状态暴露 fallback/overflow。不会改 `0x40`、跳过原生解析或共享解析器对象。`tests/check_native_parser.py` 在自建隐藏宿主覆盖返回值、注音权限、parent 继承、同地址换代、并发计数、溢出回退及 listener 开销。

原生 parse 计时使用 monotonic clock，起于 C enter 查表前，止于 C leave 清理前，不包含 aux 清理桥；与旧 JS 计时端点不完全相同。调用数与 outer 判定不变，不能直接将旧/新 parse.totalMs 相减当作优化收益。实机性能仍以同一日志页的完整打开时长和稳定帧率为准。

日志隐藏模板的简单 ruby 测量可由 `native_measure.js` 在原生 initializer listener 中完成两处既有行为：正文测量上下文不改，副文测量上下文的两个字号系数在原函数返回后按 double 乘法再写 float。只有当前 MessageLog miss、隐藏控件一致、已验证文本所有权、simple ruby 且不含混排/动画/独立层时才建立按线程嵌套的短作用域；每次测量返回后必定退出。C 侧再核对 caller、label、owned pointer 与 measuring 标记。已验证的三个注解返回地址（正文测量、副文测量、副文放置）中不满足 fast 条件的调用继续执行原 JS callbacks，保留参数修改、调用对象和清理；普通 initializer 调用原本在 JS 立即返回，现在由 C 在进入 JS 前做相同判断，原函数始终照常执行；不改 parser 控制流或绘制时钟。作用域溢出或错配永久关闭该快路径，回到旧处理。独立宿主检查与根部 scope 合约检查互补，最终仍需新游戏进程的首次日志实测。

## 富文本比例与日志来源

副语言的固定倍率与当前原生强调字号分开保存。`ruby_context_init` 创建直属副语言层时应用一次用户比例；副语言内部的原生 `<R>` 注音从引擎的固定注音字号出发，按父层倍率缩放并登记自己的倍率。颜色和粗体命令不创建注音上下文。经过版本校验的 S/s 绝对字号分支只对已登记的副语言上下文恢复倍率，主文不参与。测量快路径使用同一登记接口；容量回退仍保存新上下文，不因超限丢失字号处理。

实际注音 scale 与绝对字号修正系数使用不同字段：`factor` 保留 R 创建后的实际 scale，供嵌套 R 继承；`sizeFactor` 为该 scale 除以标签正常字号与字体基准之比，仅交给 S/s 后置修正。否则字体基准大于控件字号时，强调命令会再次乘入过小的基准，表现为正文放大而副文缩小。字体基准来自当前 label 的 font index 对应 font face；标签字号使用本次渲染前的原值。C 登记表与溢出的 JS 备用路径均使用 `sizeFactor`。`check_native_size_metrics.py` 用真实 EXE 的字号算术及生产方法覆盖不同字体基准、标签字号和用户倍率，嵌套注解与颜色另由既有检查约束。

含原生 R 注解的双语行分别保存主文与副文预测量中已有的注解边界，高度 a、a′ 各自取该行最大值。基础行距 x 不变，空副文锚点结束、主文字形输出之前，将 a+a′ 计入当前解析器的纵坐标和测量边界；首行保留偏移前起点，因此上方留白不会被边界归一化抵消。仅一侧含注解时只加该侧高度，两侧都没有时不加。整行因此向下推进，原注音相对其主文的位置不变。预测量上下文在进入解析器时显式允许原生注解并禁止输出字形，避免原生初始化之后覆盖标志；不全局开放原生的注解权限。

独立副文层与普通注音都从原生注音基准乘 `ruby_scale`。引擎的该基准由全局注音字号除以字体基准字号计算，不能把测试里的主文系数 `1` 当成所有真实控件的值；普通、颜色、S3/S5 和装备更换确认框的三层重排均保留回归。字号修正须先在真实输入和机器码路径上证明失败，不能因猜测而改变已获实机确认的行为。

最终字形阶段只补做主文的 `annotation_scale`，不再次缩小已经由注音解析器处理的副文。普通主文用 `<s>` 缩小、保留原生排版的主文用字形缩小，两种路径必须保持相同的副文规则；普通对话、动画、日志和混排共用此阶段。原生注解的预留高度也分开计算：主文注解按主文最终缩放计入，副文注解按其自身解析结果计入。字号回归须包含最终字形阶段；仅检查 S/s 回调会漏掉后处理的二次缩小，见 [放大对白验证](verification/enlarged-dialogue.md)。

S/s 尾部 `0x58687e` 是一条跳向公共命令出口 `0x587462` 的 JMP。Frida 的 `Interceptor.attach` 会追踪入口 JMP；直接挂在这里会把颜色等命令也接入字号处理，造成逐段累乘。正式代码将这条经过指纹校验的五字节分支重定向到自有 NOP 入口，在该入口处理字号后返回原公共出口。公共出口及相邻命令入口保持不变；`check_native_size_hook.py` 在隐藏进程中执行这种真实机器码分支结构，验证旧安装方式能复现累乘、新安装方式只处理 S/s。

排版范围缓存按原生解析代次持有，不按控件存活时间累积。普通注音的 opening 回调与独立副文的 base-measure 回调都是实际的创建入口；同一 parser 字形游标回退至已有范围起点时退休上一代的范围、未缩放矩阵和偏移快照。允许正文前已有装饰或其他未接管字形；同一代的多个范围继续保留。换行封闭每层主文范围，后处理仅在本代新字形或显示进度变化时执行。

源脚本身份清单独立于当前主副语言：每份合法 SCP 保存摘要、长度、函数名及静态对白的 `called` 记录索引。在已验证的 builder 调用中读取原始 VM 参数（包含资源字符串地址编码，而非显示后的中文），完整摘要验证后将其唯一定位到记录 ID。主键为资源摘要、函数和 `called` ID；所有静态对白按此主键编译局部模型，不按当前语言是否同文决定是否保留。已知 ID 缺少配对时不能借用全局同句、另一条调用或整函数的译文。

VM 的 `+0x10` 是 system-call 消费操作码和参数数量后的 PC。仅当完整字节码调用序列与编译元数据一致时，才用 PC 区分重复参数的独立记录；嵌套调用可能在元数据中父先子后、执行时子先父后，不能按局部 ordinal 相等就声称位置已对应。参数唯一时直接取得其独立记录 ID，不合并相同译文；参数重复且缺少已证明 PC 时保留冲突。动态通知继续使用独立 producer 合同，不把动态插值误认成静态对白。原生 CNG 直接读取已验证长度的资源指针，不按地址缓存摘要，也不在日志逐帧重排时重新哈希。

日志复制文本会丢失原脚本地址，因此在已验证的记录写入点保存当前对白调用身份，按 owner、slot、generation 与原始 payload 校验。首次写入和追加是两条复制分支：分别从 `0x43E209`、`0x43E2A9` 的 RCX 减 `0x180` 取得实际目的记录；追加时 R8 仍是前一槽，禁止从公共出口 R8 推导新记录。显示和隐藏测量两条构造路径记录全部分段；仅当所有分段来源一致、字节完整拼接且与身份 source 相等、没有覆写时使用该身份。即使当前全局翻译唯一，日志控件也要继承已保存的身份，供控件存活期间的语言切换使用。行高缓存使用最终解析结果，不复用不同译文的高度。`tests/check_history_identity.py` 从原始资源取得调用参数，验证跨语言 ID，`tests/check_native_log_commit.py` 执行真实原生复制分支，回调回放还覆盖连续不同正文和环回，不能只看捕获数量。

旧日志没有可恢复的真实调用身份时，允许在日志专用索引中选择完整官方候选，优先同说话人并使用稳定排序。精确索引仍保留歧义，候选不创建 ID、不进入正常剧情／菜单，也不能覆盖已知调用。原生 marker 与名称 setter 的 provenance 在同一次脚本扫描编译；可证明的静态 `chr_set_display_name` 状态按对话记录键提供名称配对，否则旧名称走官方候选兜底。

原生日志的 row-ID 命中会跳过 bind、SetText 与隐藏测量，只调用 `0x360000` 激活现有 controller。在真实 bind 返回时，以有界 sidecar 保存 controller、body、owner/epoch、全部分段的 entry 对象（包括空值）、完整 `0x188` stamp、姓名与正文。激活前只有这些字段全部一致、控件仍持有原始正文时，才重走同一来源解析入口；同槽同文换 call ID 也必须先真实 rebind。没有新增逐帧文本扫描。`tests/check_native_log_activation.py --exe ...` 在独立隐藏宿主执行已安装 EXE 的完整激活函数字节，验证 ABI、回调时序及正文不被覆盖；它不能代替实机对行高、字形和重复打开的检查。

普通对话日志的姓名和正文登记为同一个显示组；仅双语模式且组内存在实际副文时，在原生 Update 的投影阶段共同向下移动最多 8 个布局单位。行框的原生锚点、高度和正文测量底边限定可用余量，底部保留 4 个单位，用户整体偏移占用的正向空间也计入。投影沿共同父节点的 Y 轴进行，Update 返回前恢复标签矩阵；不写子节点位置、不平移行框、不扫描字形，也不累加到下一帧。无名行、正文未匹配但姓名有副文的行使用相同组规则；主动语音和单语模式不应用。销毁任一标签或重绑记录时退休旧组。

游戏过程中的主动语音按已验证布局 32 的 `items/item/text` 分类，小对话气泡按只读现场确认的布局 6 的 `root/text` 分类。确有双语副文时正文下移 8 个布局单位，与日志共用投影及恢复函数；布局退休后失效。姓名、普通剧情布局 7 和主动语音日志不继承这项规则。关闭效果、主语言单语和副语言单语全部保持原生位置，模式切换和重复 Update 不积累位移。验证见 [语音及气泡偏移](verification/active-voice-inset.md)。

旧存档中的进程 sidecar 不存在时，日志 ring 的 `+0` 仍保存公共 dialogue builder 写出的消息标记。编译器从原始八语脚本构建标记到独立 `recordKey/callId` 的候选索引；显示与隐藏测量在校验全部分段的 owner、stamp、marker、姓名及完整拼接正文后共用恢复入口。只剥离已验证可动态改变的起始表情头，正文控制及空白不删。动态姓名元数据不导致整条记录被过滤；同一调用的多语言版本可共用 recordKey，不同调用即使译文相同也不合并。标记只是恢复线索，最终翻译仍按调用 ID；候选包含多个独立调用时不会任取其一。

记录发生在连接之前时，可使用日志保留的说话人名称缩小完整对白候选。名称对应 `NameTableData` 的显式 ID，不能用表行号代替；同名角色及同角色异译仍保留冲突。显示和隐藏测量从同一条日志记录取得名称与原始正文，重新核对全部拼接片段，不从最近对白或当前场景猜测。owner 更换与已验证的创建／销毁事件会清空来源；无法确认内容的记录保留原文。

游戏文字语言改变不会重写已保存日志。新捕获记录同时保存实际原串、来源语言与经过结构验证的稳定调用键；当前源脚本摘要发生变化时仍按该调用键解释目标译文。不同语言的实际 call ordinal 由目录的 `called_ids` 明确记录，不能直接复用另一个语言的序号。旧记录缺少调用身份时，`history_contexts` 对全部来源语言的完整正文及姓名建立索引，目标对共享存储、冲突显式保留，运行时仅创建命中的局部解析器。这个备用入口限定在原生日志显示和隐藏测量路径，不更改普通菜单的来源语言，也不伪造旧对白 ID。真实截图对应的五条对白以八种来源、日英两个目标回放，见 `tests/check_mixed_history.py`。

动态系统提示另由 `dynamic_producers.py` 读取原始 PAC/table 编译。数值槽保留实际 opcode 决定的全角／半角宽度；食谱和物品获得提示按有限 item ID 生成完整句子，避免将多个富文本片段分别塞入注音。缺少无关语言或某语言有同名歧义只产生审计项，不全局删除整条多语言记录。每条完整提示在单行情况下拥有一个副文层，颜色状态独立封闭。

`item_help_composition.py` 从原始效果参数类型及槽位建立有限组合规则：磁盘 `SkillParam` 为 `+0x30..+0x70` 五个槽，`ItemTableData` 为 `+0x3c..+0x7c` 五个槽。原始实例的五槽检查与通用类型组合的三槽枚举分开，避免将全部排列扩展成五阶组合。概率、回合、强度和属性组按游戏各语言的 LINK 与模板顺序组装，只进入详情专用模型；拆开的状态标签作为完整候选加入普通冲突检查。构建报告保留未覆盖的混合效果组，不能把这些组直接算成已证明的屏幕漏译或成功覆盖。

道具 normalizer `0x23f010` 的源对象是 `0x23ef20` 返回的原始 `ItemTableData` 行；现场 ID 4050 与 PAC 同时证明首槽 1092、第二槽 1033。此前只读 `+0x6c` 后三个槽会漏掉这两个效果。`SkillConnectListData` 另外决定组合分支，不等同于单个效果的 parameter type；原生分支 17 将首个 name 与后续 stat＋format 按 LINK 拼接，每段独立保留自己的数值。成员从资源读取，不在代码中列举道具名称。

完整数值模板优先于可吞入任意文字的 `%s` 拼接模板；同级模板产生不同译文时仍保留冲突。该顺序不改变普通对白按调用 ID 解析的规则，也不允许按第一个命中解除两个具体资源间的歧义。

格式参数按类型处理：仅 `%s` 使用名称配对；`%d`、`%u`、`%g` 等数值槽直接保留捕获值，不再把数值当作词条二次翻译。原生 producer 明确声明的全角数字格式仍由其自身合同处理。

同文动态道具通知的身份由 `dynamic_identity.py` 编译。已验证的 SCP helper 转发指令把脚本 SHA-256、helper 名、command-8 PC 和完整原始参数向量绑定到外层物理调用。运行时验证整段输出模式后，沿现有 builder 输出缓冲传递该身份；日志保存稳定记录键及实际来源语言。无法证明转发帧或一个向量对应多个调用时，不生成身份，也不猜测 VM 父栈偏移。普通无歧义 producer 渲染仍独立可用，身份覆盖与文本渲染覆盖分别审计。

七种回路标题从 `ItemKindHelpData` 的类别模板提取“X 属性”和“属性值”两个文字字段。原模板前后缀只负责确认详情上下文，标签配对进入已有详情子模型；不再编译整行生产者，也不依赖图标 ID 或图标数量。原始括号、图标和数值保持不变，副文仅对应两个标签。独立标题、标题加说明、标题加未知后缀共用此入口；未知后缀不因此取得译文。全词库会令这些短标签与其他领域发生冲突，所以不能把它们提权成全局词条。`tests/check_quartz_labels.py` 使用完整目录验证八种来源语言、单／多图标与主副文，避免缩减词库掩盖冲突。

`TextTableData` 的显式文本键与其他文本表共用原生表指针身份解析。该表两个字段分别是稳定键和文本的可重定位指针，编译器按键生成模型，运行时验证完整表头、字符串池和记录字段。已有 native hash-key 入口不能代替直接文本指针入口；“休息”等短词即使在全局有歧义，也能在实际表身份成立时取得对应译文。堆复制失去来源或多个真实身份冲突时，仍不能任取首条译文。

人物属性标签的全角加号来自 `HelpIconList`。该表的非显示标量是布局参数，四项标签共享相同值，且各语会插入额外排版行，不能据此分配跨语言 ID。编译器保留每语原始行号，以已有 `SkillItemStatusData` 状态 ID 的格式前缀识别仅终止加号字形或加号前水平空格不同的实际帮助标题，生成精确来源别名。目标仍使用该状态 ID 的配对，避免没有变化的英文来源因中日加号变体产生新冲突；正文措辞、内部空格、其他符号不归一化。此入口继续负责状态标题字形别名；完整 HelpIconList 的条目、正文和续行由 table_alignment 按主题与条目结构对齐。

详情数字规则按可证明必现的字面片段建立候选索引，未知正则形状保留完整备用扫描。索引不改变原规则的匹配次序或冲突判断；同一模式已由详情规则处理时，普通规则的重复副本不再执行。真实完整模型中，一次冷详情解析此前会执行约 189 万次正则匹配；索引将候选缩到约 152 次，离线中位数由约 230 ms 降至 0.12 ms。该结果只覆盖解析阶段，不能当作日志整页打开或绘制帧率的成绩。`test_runtime_text.js` 保留未知模式、重复模式冲突、完整详情锚点和非详情输入的回归。

`tools.audit_locale_coverage` 审计全部完整对白和表项的语言缺项与原文冲突；`tools.audit_dialogue_coverage` 进一步区分全局配对和编译调用身份。统计是资源／解析路径覆盖，不是屏幕漏译数量。语言矩阵分别核对资源目标值与 Python/JavaScript 行为，不能仅凭两实现返回相同内容判定翻译正确。真实游戏控件是否传入对应身份仍需原生路径验证。

## 日志性能的边界与后续方向

双语复用原生注音布局，减少了另写一套渲染器的成本，但也继承了游戏文本控件的生命周期：打开日志时集中计算大量历史记录的行高，显示期间部分控件仍反复解析。副文增加了字符解析、测量、几何修正和绘制工作；这不是仅更换字体、调透明度就能消除的 GPU 开销。

2026-09-26 的本地候选实测中，隐藏测量循环首次运行从上一候选的 697 ms 降至 475 ms，后续三次为 158、133、79 ms。原生 fast 分支确实命中，未发生作用域错误或容量回退，但用户仍确认可感知的开页卡顿。这些计时只覆盖隐藏测量阶段，不能当成完整开页延迟，也不能与嵌套 setter、parse 计时相加。当前优化有效，但没有证明数量级改善或消除帧率损失。

进一步压低单次回调成本只能减少现有工作中的一部分。若要争取约十倍的端到端改善，需要减少工作量本身，例如只排版可见历史记录，或持久复用最终排版并停止无变化帧的重复解析。前者需要接管滚动高度、行索引与可见项生命周期；后者需要完整的字体、样式、图标资源失效规则和原生对象所有权管理。现有标量行高缓存不等于可复用完整字形对象，不能直接跨帧保留指针或清除原生重排标记。提前测量只能转移停顿，不能证明总成本下降；游戏布局调用也不能直接搬到任意后台线程。

因此本轮保留已经验证的优化，停止继续追加局部性能补丁，将双语日志卡顿列为已知限制，推荐单语言显示配合按住切换副语言。不存在“已证明无法优化”的结论；只是当前没有同时满足约十倍收益、布局正确性和可控维护成本的已验证方案。后续若重新开展，应先对日志生命周期的替代方案做独立验证，再决定是否替换现有实现。

经原生构造合同证明的完整效果句不再要求额外的说明文字才能匹配，包括说明为空的道具；它们作为普通全局候选保留真实冲突。依赖语境的短词、字段片段与回路两段标题标签仍使用对应上下文。效果的聚合类别读取 `SkillConnectListData`，不能把所有单整数参数误判为概率类型。

无参数连接构造器同时覆盖单成员和多成员，不能以聚合长度排除实际 `stat + format` 输出。危机回合的 connection kind 2 使用资源成员、实际回合槽位及对应箭头构造完整模板，提前绑定字符串参数以保留不同语言的参数顺序。状态百分比使用 `name + value`，来源的百分号宽窄别名共享同一官方目标。

含动态物品插入的 command-8 弹窗可保留连续静态说明块，物品所在动态行不冒充静态文本。跨语定位使用同函数内唯一的非文本调用参数序列；重复序列仍要求完整函数形状与调用位置。连续静态行作为整体配对，不把视觉换行当作翻译边界。反向检查入口及未验证过滤条件见 [详情与弹窗过滤反查](verification/detail-filter-reverse-audit.md)。

## 已有标签字体材质与复制地点名

字体 face 切换后，原生 SetText 和字形重测不会自动更换已存在标签的材质图集。Update 按 font generation 调用 `createFontMaterialRefresh`，比较 normal 和有效 shadow image，再按需调用标签虚函数 `+0x28`（`0x588B40`）更新普通字形 primitive、退休旧 icon/shadow batch。释放后的 shadow handle 清零；完成后才登记新代次，setter 元数据采集不能提前登记。稳定帧不重复检查，新标签已使用新图集时不重复重建。

地图列表与详情的 `spot_name` builder 先复制 MapJumpSpotData 名称并删除 LF，SetText 时已丢失表指针。该控件家族使用由完整地点表生成的 `map_spot` 上下文；不按具体地名补词，不覆盖 ViewerMapData 的真实措辞差异。原始八语资源、完整目录与最终副文审计见 [字体、性能与地图地点检查](verification/hud-performance-and-map.md)。
