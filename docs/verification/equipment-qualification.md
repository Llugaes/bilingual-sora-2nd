# 装备限定前缀：共享构造修复

基线为 `b9aedb8600009d577601f4a45d1561b7df000389`，用户已确认 r2 其他表现通过，本次新增反馈为“女性专用／男性专用／缇妲专用”没有副文。只修复该构造族；第二轮内存与解析器大范围重构仍按原计划等待单独推进，不发布。

## 现场与根因

2026-10-11 在 r2／游戏 PID 37032 的只读采集中，控件为 layout 33、`root/help/text`，主简中、副日文。读取的是已经改写后的显示串：限定前缀没有副文锚点，后续 HP、魔法回避率与说明已具有副文。没有追加 Frida 会话或修改当前游戏、配置。

按资源构造重建的完整输入交给 r2 正式模型后，输出加上原有 `<s27>` 与现场逐字相等。该输入属于资源重建，不冒充原始 SetText 抓包。单独的三个限定标签均可译；进入完整属性／说明组合后，前缀被视为 opaque。旧 equipment 拆分规则只识别半角方括号，而中日韩资源使用全角括号。原生标题合同遗漏了限定前缀，角色模板又缺少限定的参数域，因而有明显语种差异。

`ONLY` 与 `HOLLOWCORE` 在七种语言中同文，德语顺序不同。本次只采用已证实的 `TXT_ITEM_HELP_ONLY` 调用，不能用全局 `%s` 模板首条命中解决歧义。

## 原生与原表合同

依据 CAB62 EXE（SHA-256 `cab62e5872222efb2aaf272be47f14263db4e7132ad7df5255db8efbee9959ea`）的离线反汇编与八语 PAC：

- `ItemKindHelpData +0x10 == 6` 的完整说明分支在 `0x349173` 开始；资格选择在 `0x3491e8..0x349320`。它与料理／Tools 的 kind 3 分开。
- 原始 `ItemTableData` 的 `+0x20` 是资格 flags 字符串，M/F 经加载器转换为原生位值 4/8。M 优先于 F，随后可独立追加单角色限定，不假设二者互斥。
- 原表 `+0x08` 为 uint32 角色 ID 数组，`+0x10` 为 uint32 count；只有 count 1 且 ID 非 `0xffff` 才走 ONLY。
- 角色 ID 查 `NameTableData` 首 uint16；用 `+0x40` 默认模型 key，或在 `0 < +0x48 < 0x8000` 且备用 key 非空、相应运行态位开启时用 `+0x50` 备用 key。key 再查 `StatusParam +0x00`，显示名来自 `+0x198`，并非直接采用 `t_name.name`。
- 装备正文调用 `TXT_ITEM_HELP_FORMAT2`（`0x34946a`）和 `FORMAT4`（`0x3495c7`）。八语括号、内部空格、结尾空格和换行均保留原资源；不从 FORMAT5/6 猜测它的真实调用。

八语原始资源均为 1,382 件物品，kind 6 有 225 件，其中限定装备 66 件：男性 32、女性 32、单角色 2；角色 ID 均为 6，实际为耶梦加得与耶梦加得＋。角色名链、限定 metadata 和已核对属性在八语一致，没有角色缺项、StatusParam 缺项或姓名冲突。两个难度 section 均由相同模型 key 得到相同显示名。全部 66 件都有非空说明和非零属性。

合法成员由原表枚举，不写死 66、角色 6 或“缇妲”。以后同一构造新增合法角色／装备时从资源自动编译；未知角色、缺译、同模型 key 异译不获得标题权限。

## 实现范围

`item_help_headers.py` 将真实限定和 FORMAT2/4 编译为既有 `compact_rows`，沿用现有去重与完整效果校验。当前生成三种共享标题，分别关联全部 66 件物理物品。

跨语言回归还发现原生正 HP 使用 `SkillItemStatusData id 0 / format`（`0x350cc8..0x350e9e`），而非通用 `name + value`，后者会丢失韩、法、德、西文格式中的空格。仅加 compact 标题仍无法接管韩文实际完整输入，因此不能用无空格的模拟串宣称八语通过。

编译器从当前两条角色装备的原表数量生成精确 HP 成员，随标题保存在既有 `owned_effect_units` 中。相同标题去重时合并两条合法数量，并拒绝同源异译。Python 与游戏内 JavaScript 的 compact 分支各补上已有公共属性解析函数的第五个参数，与普通完整标题使用同一接口。规则、词序和参数域只在编译数据中维护，没有新增语言分支、关键词别名或第二套组合算法。`native_agent.js` 及原生布局组件不改动；r2 的字号和首行原点规则继续使用原组件。

编译器只在读取离线资源时解析姓名链，不增加每帧原生读取或新钩子。它处理已知参数域；本次没有实施整机内存峰值优化，也不据此声称性能收益。
