位置检查目前把现场字形重放到最终几何出口，只证明该出口未消除已存在的下移；它没有重建完整字体解析及原点计算。若修复发生在上游测量/原点边界，必须另建对应的真实入口验证，不能为了使重放转绿，把补偿强塞进几何出口。最终坐标仍需新候选在新游戏进程中核对。

进一步只读采集了当前游戏的 `text_table_global + 0x6a4`，原始字节 `000040c1` 对应 float `-12.0`。已校验的 `line_ruby_origin` 机器码在符合条件的首行用它调整原点；同字首个字形满足 `14.25 × (15 / 18) + 12 = 23.875`，与实测相符。该全局值是引擎输入，不是生产修复中的补偿常量；回归需要覆盖不同输入值，以及测量、单语和普通正文的拒绝边界。

## 实施结果

`rubyContextCallbacks.sizing` 是普通 owned ruby 的唯一小字号度量入口。它使用当前主文的整数像素值与原生副文的真实字体基准，将最终副文限制到主文减 1 像素的上限；用户原本更小的副文倍率不再缩小。该判断同时供测量、绘制和首行原点修正使用；小字号日志预测量回落已有 callback，普通字号保留 C 快路径。没有改动文本配对、用户设置、最终 C/JS 几何算法或增加新原生钩子。

适用范围为已有普通 owned ruby 路径、已验证字号范围内的小控件，跨页面生效；mixed/layered、原文自带 R、原文或输出中显式 S/s 保留原合同。此次没有声称这些排版策略的所有小字号都已实机验证，也没有为了它们重写已正常的强调/混排处理。

| 原标签字号 | 原主/副字号 | 修复后主/副字号 |
|---|---|---|
| 18 | 15 / 18 | 15 / 约 14 |
| 21 | 18 / 18 | 18 / 约 17 |
| 24 | 20 / 18 | 不变 |
| 32 | 27 / 18 | 不变 |
| 48 | 41 / 18 | 不变 |

首行修正执行真实 `line_ruby_origin` 调用前后保存/恢复原点，使用引擎当次输入；正常字号、测量分支、后续行与既有 speaker/mixed 规则保留。76 组原点场景覆盖多种原生 margin，不把实测 `-12` 固化为生产常量。

独立审查还发现新度量缓存的延后字体失效问题：同文同字号改 font index 时，旧结果可能把 14 像素副文放大到 28。已先冻结失败，再使 Update/Reset 的共同失效谓词检查计算时的 font index 和原生 ruby 字号，包含 normal→small 与往返切换。字体对象发布仍由既有 font epoch 失效；每帧不遍历字体链。28 组延后变更由失败转为通过，复核关闭该 finding。

定向宿主共 19 项合同通过，包含 24 组日志测量与 24 组绘制度量、低倍率保留、倍率单调、同控件单语/禁用/恢复和同代重复处理。原有字号宿主用已校验 CAB 的 S/s 指令另执行 96 个组合与 16 个对照通过；原 D8 EXE 专用检查的门槛没有放宽。定向红/绿与缓存红/绿记录为 `owned-title-layout-{red,green}.json`、`owned-title-layout-cache-{red,green}.json`；当前生产脚本 SHA-256 为 `5ab52bf5c3adc36e891425537f71a08417bf64d9abcced50665b22238a4cb83c`。
