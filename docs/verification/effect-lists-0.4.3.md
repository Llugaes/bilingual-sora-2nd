## 问题与边界

用户报告主英副日下带原生边界的 Side Attack Bonus、Back Attack Bonus、Sure Hit 未关联。0.4.2 的完整运行模型能翻译裸名称，但带逗号的片段不能解析；加上真实技能说明锚点后仍失败。

原始八语资源 `TXT_ITEM_HELP_FORMAT8` 在日、中、韩为全角斜线，在英、法、德、西为逗号加空格。它与 `TXT_ITEM_HELP_LINK` 的内部聚合连接符不同。磁盘 EXE 中的详情 builder 分别引用 FORMAT8、效果名称和 HITTING；这是组合构造依据，不能把逗号变成全局字典项。

新规则只进入已有详情模型，要求完整资源说明或已有详情标题先完成上下文准入。成员来自效果字段、已经证明的参数构造器和原生额外效果标签；完整配对、参数类型、语言缺项与同文冲突仍限制准入。拒绝表达式按最终获准模板集合建立，覆盖冲突、位置参数、超出数值槽上限和未绑定的百分号，防止更宽模板重新识别。未知图标所在的完整列表拒绝后，拆分片段也不能重新使用列表规则。未知成员、纯标点、范围标签和普通菜单不会获得新权限。

完整资源成员先于较短标签；复活加回血等已经证明的完整句保留官方措辞。新列表先于自由 `%s` 模板，避免前面的效果被吞成参数。数值和图标按既有合同处理；只有已识别、包含内联图标的完整列表进入已有富文本副文排版路径，其他详情继续原排版。

## 可复现验证

`tests/test_detail_effect_lists.py` 回放八种来源、主文、副文的 512 种配置，覆盖两项、三项、五项、成员顺序、前后边界及最后逗号被控件裁切的情况；对照原资源目标字串和最终注音，并检查 Python/JavaScript 一致性。另有冲突、语言缺项、完整参数成员、自由 `%s`、范围角色、原生图标与未知图标的边界回归。

```powershell
python tests/check_detail_effect_lists.py --game GAME_DIR --output generated/effect-lists-full.json
python tests/check_detail_effect_runtime.py --game GAME_DIR --output generated/effect-lists-native.json
```

第一项先独立枚举八语 PAC 的全部物理记录和五个字段位置，保留空字段、语言缺项、重复及冲突，不依赖词库提取器的准入结果作为原始分母；另核对原生标志及两个连接符。再使用完整目录编译 64 个来源到目标模型，记录词库字段和已证明类型模板的分母与拒绝原因，逐项比对成员配对。每种家族、完整字段角色和参数形态取代表，回放两项、三项、五项组合及最终副文；裸格式半句不伪装为完整游戏效果。与 0.4.2 JS 对照普通菜单和标点行为。它验证构造器闭包，不声称所有合成顺序都在游戏中出现。

第二项构建正式入口的完整英来源、英主、日副模型，通过生产的 indexed wire 在自建隐藏宿主中加载 Frida V8，检查报告片段、数值聚合、复活、内联图标及组合的完整译文和最终副文，并消费模型中的拒绝表达式。未知图标及未知成员的完整译文和渲染与 0.4.2 比对。冷渲染性能每次使用新解析器，不以热缓存命中代表首次打开页面。

这些脚本只读已安装游戏资源，不启动或附加游戏，不修改玩家配置。原始资源、截图、完整运行模型与详细日志保留在 ignored `generated/`，不进入源码包。
