# 2026-09-29 重复表身份修复

范围是上一轮反向清单中的 298 个简体表字段：成就 144、帮助 94、主动语音 53、姓名 5、
任务历史 2。它们是 MOD 生成的结构键重复，不是游戏对白 ID 重用。本轮没有改动脚本对白 ID
或无身份旧日志的兜底规则。

## 原因与修复

| 资源 | 原因 | 新对应方式 |
| --- | --- | --- |
| PlayRecordData | 49 行中的首标量是分类，不是唯一 ID；38 行在去掉文本地址后结构相同 | 保留完整有序记录位置，以非文本结构序列校验跨语对应；每行独立键，标题同名也不合并 |
| ActiveVoiceTableData | 同一会话编号下可有多条说话人、条件、语音信息相同的记录 | 会话编号＋该会话内有序位置；校验整个会话的非文本结构，保留每条正文 |
| NameTableData | `0xffff` 占位编号与相同模型资源串不能区分开发名称、别名及正式名称 | 保留经过八语结构序列核对的独立表记录位置；不按名称文本或模型名合并 |
| t_quest_fc / NoteMainHistory | 两条不同历史事件使用同一个条件值 14187 | 保留历史文档的有序记录位置与完整条件序列 |
| HelpIconList | 主题、分页、列宽和图标组合不能唯一标识帮助条目；法德西文有额外续行 | 主题＋主题内条目顺序，核对图标序列；忽略分页及列宽差异，续行归属于前一条目，字段先配完整段落 |

这些是表资源的结构定位键，不能冒充游戏脚本对白 ID。八语原表记录数：成就 49、主动语音
2,481、姓名 1,583、任务历史 11；帮助表为日英简繁韩 131、法 143、德 166、西 157。
帮助条目内的分页位置会变，不能按全表行号直接跨语配对。

`table_alignment.py` 集中承担这五类有序资源的对齐，其余字典型表继续使用原记录身份。
输出保存每种语言的物理行来源；`compile_table_identities` 使用同一来源登记真实字符串地址，
不会在运行时重新按中文猜记录。原生选择器仍校验表头、字符串池、记录内容和字段地址。
同一池地址对应不同译文时仍保留冲突；不同记录拥有不同字符串地址时能各自解析。

完整帮助字段跨多行时保留完整段落配对。只有实际字段分段数量相等的语言才额外生成单行配对，
不把不等长段落硬按行号对应。独有分段仅被完整段落覆盖时，审计单列 aggregate-only，
不计作单控件直接翻译已通过。

## 缓存、性能与交付

新模块加入目录缓存指纹、候选组件清单和 `release-files.json`。更新后会使旧目录失效，
避免旧拒配结果继续被缓存，也避免本地有文件而安装包漏带。对齐和续行分析仅在目录构建执行；
运行时使用已编译的地址索引，没有增加逐帧扫描原表或全词库的步骤。

两组当前完整模型重新编译耗时分别约 52.7、52.0 秒（目录已构建），不能作为首次安装全流程
提速证据。JS 冷回放含表池校验的 P95 约 1.6 ms；使用 Node 内存适配器，不代表游戏帧耗时。

本轮交付开发候选；未发布新版本 Setup，也未重启、重新附加游戏。实机画面仍待正常游玩验证。
