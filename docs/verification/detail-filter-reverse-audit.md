## 已确认根因与修复

| 输入 | 原来的失效条件 | 修复与检查方式 |
| --- | --- | --- |
| `HP吸收` | 无参数效果连接只生成两个及以上成员；原表 name 是 `吸收HP`，实际输出是 stat + format。全局另有同文词条，所以裸词测试掩盖了详情子模型缺项 | 同一构造器支持单成员；使用本次真实完整技能原串回放，包括颜色、图标、延迟、必中和说明段 |
| `危机时4回合…↑` | 旧普通回合规则要求 connection kind 4 / 参数类型 16；危机效果实际是 kind 2 / 类型 9，英文参数顺序也不同 | 读取实际连接成员与槽位，编译时绑定属性和箭头，运行时仅填入回合数；检查文字箭头和原生图标两种输入 |
| 命中／回避等百分比 | 只管理 format 字段，没有覆盖 name + value 的完整百分比形式 | 编译全部 32 个状态记录（去重后 26 个构造器）；百分号宽窄来源别名共享官方目标，不形成竞争译文 |
| `解除减益･无效` | 原生专用分支连接通用解除标签与 effect 97 的 format；单独 name 配对不等于完整连接文本配对 | 使用资源中的 LINK、DEBUFF_CANCEL 和 format 构造整段，不添加翻译词特例 |
| `已取得克萝赛的礼服！` | 后续物品插入令整条 popup 不满足纯静态条件；中韩资源还把颜色标签与正文拆成两个参数 | 保留动态插入之外的连续静态说明块。唯一物品／控制参数序列用于跨语定位；重复序列仍检查完整函数与调用位置。完整块覆盖不完整字节码片段，不能覆盖另一条不同的完整译文 |

弹窗静态说明按连续块配对，不按视觉换行逐句配对，避免把中文第二行误认为日文同位置的独立句子。
opcode 17 所在动态行仍不伪装成静态行；未知操作码或无法确认宽度的操作数保留为缺口。

## 反向清单与保留边界

- `tools.audit_detail_filters` 从完整目录列出没有进入全局精确索引的完整资源记录，保留来源键、
  主副译文、歧义／参数化分类，并重放本次构造器。缺少全局精确索引不自动等于漏译：脚本 ID、
  表身份、动态规则和详情上下文是另外的入口，清单不会把它们假装为已验证。
- 804 组槽位中，510 组的全部 ID 在效果帮助表中，294 组含该表无法识别的联合槽位。后者保留
  每个原始槽位、未知 ID 和说明资源键；不能把整组称作无用文本，也不能猜测未知槽位参数。
  已知单效果可能已通过同连接族的其他资源进入构造器，这与完整组合是否验证是两件事。
- 899 个弹窗调用中，857 个纯静态调用的八语整段文本已与目录逐字核对；42 个动态调用分别为
  opcode 17 共 40 个、opcode 18 和 23 各 1 个。既有 BP／旅店数值生产者承担后两项。
  动态物品插入、书籍登记、继承奖励中仍有不能完整配对的输入，原参数逐条保留。
- 32 个状态记录全部参加编译，6 个与其他记录的完整目标相同而去重；不是遗漏 6 个状态。
- 只含分隔横线的资源说明不作为真实详情锚点。该类只检查详情解析器，不用虚构说明段制造通过。

原资源反查还覆盖 1,082 个脚本文件及 315 个表文件。63,128 个静态完整调用全部被目录收录。
2,010 个未单独收录的代码字符串片段由“单语完整函数对齐”条件排除；它们包含正文，不能概括为
垃圾字符串。唯一未单独收录的调用参数是旅店 `要支付` 前缀，完整付款提示已有数值生产者处理。
另有 298 个表字段因重复身份被拒配：成就 144、帮助 94、主动语音 53、姓名 5、任务历史 2。
它们包含可见文本，仍作为配对缺口保留；本轮没有宣称解决这些表的跨语身份。原目录中的无歧义
其他路径是否能覆盖它们，需要另行按具体字段验证，不能由目录排除数量推算屏幕漏译数。
