### 需求边界：已确认 P1

`native_agent.js` 曾用 `layered && multiline` 开启高度预留，随后计算 `max(0, 副文测量高度 + ruby_gap - 原生行距)`。独立副文也用于普通对白的颜色、控制标记、图标及逐字显示，因此该条件覆盖了远多于提示框的文本。

`runtime_text.js` 的主副语言能逐行对应且无富文本时可使用普通 ruby；格式内容或换行结构不同时使用独立副文。`wantedText` 还会把逐字显示的普通 ruby 改为独立副文，让副文跟随主文显现。因此同一句话在实时对白和 log 中可能走不同路径，不能由这个实现策略决定是否增加行距。

| 输入／状态 | DEV3 是否会多加普通副文高度 | 本轮处理 |
|---|---|---|
| 静态、纯文本、主副语言逐行对应 | 否 | 保留原推进 |
| 多行 C/c、K、S/s、I 等富文本 | 是 | 撤回额外预留 |
| 逐字显示的普通多行对白 | 是 | 撤回额外预留 |
| 主副语言换行不同，转为独立副文 | 是 | 撤回额外预留 |
| 提示框、读档确认框、菜单混排 | 符合上述输入条件时是 | 撤回额外预留，不以窗口名猜测 |
| 原文自带 R 注音 | 原有 a/a′ 与新公式相互作用 | 保留 0.4.0 的 a/a′，删除新公式 |
| 单行普通副文 | 否 | 不改变 |
| 关闭、主单语、副单语、没有实际副文 | 否 | 保留原恢复行为 |
