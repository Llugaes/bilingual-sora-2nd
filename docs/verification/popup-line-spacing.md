**状态：0.3.34 修复已撤回。** 2026-10-04 用户实测出现菜单、提示框和普通对话高度异常；只读采集确认五行提示框测量高度为 2137 个布局单位。以下是当时的有限回归，不能作为修复成功证据。0.4.0 恢复 0.3.33 排版并保留连接入口校验修复；原有多行拥挤仍待本地候选实机验证。

## 2026-10-04 本地候选：使用零原点测量

**此轮候选未通过实机验收。** 用户反馈读档确认框仍有大面积留白，下面的选择框被挤到屏幕底部。零原点检查通过不足以证明父窗口使用的是最终排版。该候选未公开发布。

旧检查把子控件结束边界直接设为单行高度，遗漏了真实解析器的坐标语义。

实测使用独立 DEV 目录，复制已校验的运行依赖、配置和当前映射缓存。设置标题、悬浮条与托盘明确标记 DEV；开发目录不含正式安装清单，更新器不会覆盖它。启动前正常退出正式版工具，防止两个工具同时连接。正式版文件与配置分别保留，实机验收仍为待完成。

- `0x58709f` 在零原点测量副文；`0x58714a` 复用同一个子上下文，重新初始化后绘制。初始化会清空边界，因此必须在这个调用的入口读取前一次测量。
- `parse_text` 的 `0x587824/0x58782e` 将边界起点设为零。位于后续行的绘制结果包含页面 Y 位置；把这个包围范围作为新增行高，会递归加入前几行的高度。这是 0.3.34 的窗口膨胀原因。
- 候选仅为已接管的双语多行副文保存零原点高度。主文原注音仍单独计算；副文的整行高度已含原注音，不再重复相加。无需增加解析调用、逐帧扫描或控件名称白名单。

## 后续本地候选：在窗口消费高度之前完成排版

只读采集发现同一个 layout 8 确认框的背景高度为 655，正文测量高度为 427，实际字形包围高度约 436。原生窗口加 60 的内边距，因此它创建时使用了 595 的旧正文高度，差值 168；不能靠调整背景固定高度或行距掩盖。

原生系统弹窗先重置状态再 SetText；`0x536c50` 根据弹窗模式切换文字 flags 的 bit 4（逐字显示），该操作可能晚于 SetText。`0x533e4d` 初始化文本解析器，紧接着 `0x533f42` 消费已保存的正文高度，期间没有 Update。旧逻辑只在 Update 修正晚绑定 flags，已经来不及影响父窗口。

候选在原生 reset 边界复用与 Update 相同的字号／flags 判定，更新已接管文本的排版后再交还原生初始化器。变化后的文本通过原生 SetText 完成测量；文本相同但几何参数改变时额外测量一次。稳定且没有测量脏标记的 reset 在 C 层直接透传，不增加逐帧 JS 扫描。Update 自己的嵌套 reset 保留原有逐字进度恢复流程。

该边界使用原生 replacement：在 Interceptor listener 内调用 SetText/measure 会抑制下层钩子；replacement 中的 NativeCallback 返回原生调用链后保留解析钩子。`check_native_popup_lifecycle.py` 专门保留这个失败对照，不能用普通 JS 函数调用模拟代替。

验证入口新增到 `tools.dev check`：

- Node 正式渲染器回放含未翻译等级／时间的九行确认框，两种动画 flags 转换均在首次 Update 之前稳定，重复 reset 不再重写。关闭效果及主／副单语言不产生双语层。
- 隐藏原生宿主执行 `0x536c50` 的 87 字节指令夹具、生产 preparation 和 production reset bridge。构造器在 Update 之前读取最终高度；无修正及错误的 listener 两种负对照必须失败。
- 原生宿主的字体测量和父窗口 padding 是有界测试替身，不能当作真实游戏截图验收。新候选仍待用户实机确认；正式版保持 0.4.0。

## DEV2 实测未通过：已有原生行距被重复预留

用户确认异常拉长有所改善，但提示框仍偏松，部分带换行的对白／日志还出现首行留白；将用户额外行距从 6 调到 3 没有解决根因。DEV2 因此未通过验收。

两次只读采集的 layout 8、`root/text` 均为字号 33、flags 865，但游戏本身的有符号行距 `label+0x2f4` 不同：原“零力场发生器”重叠采集为 **-1**，DEV2 的“缇妲的导力炮”提示为 **15**。不能把同一控件路径当作同一行高配置。`0x587966..0x5879a1` 用上行底边加这个原生行距，再增加 `parser+0x16c` 行号；旧候选不区分首行，也未扣除已经存在的间距。

下一候选保留原生注音的 a/a′ 预留；普通副文不再让首行下移，后续行仅补 `max(0, 副文测量高度 + 主副文间隔 - 原生行距)` 的缺口。用户的额外行距独立保留。规则来自每个控件的实际字段，不按文本、窗口 ID 或游戏语言枚举。正常／两种单语言不执行这项补偿。

新增回归先在 DEV2 失败（首行额外下移 23，而预期为 0），再检查修正。矩阵覆盖原生行距 -1／0／15／24／40、带表情控制的两行对白、颜色提示、原生注音、首行及后续行、反复重建和单语恢复。既有五行重叠样本仍检查相邻字形不碰撞，不能通过删掉防重叠检查来让新测试通过。

隐藏宿主增加 59 字节原生换行夹具（SHA-256 `9ca28babc6bcfa22843a612f47900a5d4fdfa3c7452c5632fe03a888d5bfc026`），与受支持 EXE 核对一致；240 组组合实际执行原生换行、生产回调和重置构造器。仍不代替完整字体渲染和用户实机验收；本候选只分发至本地 DEV，正式版保持 0.4.0。

## 原因与修改

带颜色／图标的多行说明使用空注音锚点和独立副文。旧代码只补原生注音的高度和用户额外行距，未给普通副文预留完整高度；最终对齐将副文放到本行主文上方，却覆盖了上一行主文。

在已验证的原生解析结束入口读取子上下文的真实边界，将所需高度计入当前主行及测量边界。使用同一个入口处理绘制与测量；完整副文已包含原注音时不重复叠加。颜色、图标、字号由原解析器测量，不使用文字白名单、固定字号估算或新一次解析。
