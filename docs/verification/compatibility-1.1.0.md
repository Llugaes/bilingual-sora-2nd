## 兼容问题的实际状态

本机 `sora_2nd.exe` 文件版本为 `1.4.0.0`，大小 13,470,208 bytes，SHA-256 为 `cab62e5872222efb2aaf272be47f14263db4e7132ad7df5255db8efbee9959ea`；Steam build 为 `25721473`。该样本与此前核对的 1.04 相同。用户自行更新工具后，正式 1.0.4 的 675 个受管文件与清单一致，应用和原生依赖预检通过，70 个原生位置通过。

用户启动游戏后，现有正式 1.0.4 后端实际达到 `phase=ready`、`resident=true`、`failed=false`、`error=null`；字体为 `ready`，来源语言 `zh-Hans` 与游戏匹配，完整 `indexed-v2` 模型加载成功，初始 `matched=4`、`modified=4`。这证明当前样本已连接并处理文本，不证明整个游戏的显示效果。旧 `native-error.log` 的连接重置来自 10 月 5 日，不属于本次错误。

本轮未复现原先的“游戏版本或原生依赖不兼容”提示，不能将下面的性能修复表述为已确定并修复了该提示的根因。窗口采集曾返回与目标游戏不符的画面，这些截图不作《空轨2》显示或帧率证据。

现有兼容机制已经按实际使用的函数、调用关系、数据及必要续段重新定位，不比较游戏版本标签或整个 EXE 摘要。本轮保留字段布局、参数、必要控制流和运行态接管校验。无关更新可通过已有定位机制适应；实际依赖结构变化仍需适配。详见 [EXE 兼容检查](exe-compatibility.md)。

## 模型加载阻塞：失败与修复

现有 1.0.4 原生耗时记录中，一次 SetText 回调进入等待约 4,666 ms。对同一完整 wire（173,823,360 bytes）在自建隐藏宿主中让原生回调持续运行，并在期间执行生产 `modelpackedfile`：修改前最长等待 5,196.879 ms，总加载 5.2145 s，超过原有 100 ms 门槛。独立分段测量为校验约 2,587 ms、构造约 864 ms；加载持有 Frida JavaScript 锁导致原生回调等待。

修复限于完整模型加载：分块读取文件，在校验和构造循环中按时间预算让出锁，最终同步发布完整模型。使用 Frida [NativeFunction cooperative scheduling](https://frida.re/docs/javascript-api/#nativefunction) 调用 `Sleep(1)`，约 12 ms 工作预算后让出一次。`Sleep(0)` 的对照仍出现 1,166 ms 等待，因此没有采用。加载检查点不保存在活动解析器中，正常渲染保留同步路径。

相同隐藏宿主、完整模型及原 100 ms 门槛下，当前实现总加载 1.9631 s、最长原生等待 54.286 ms、回调 22,816 次，通过。4 ms 预算的中间版本虽通过等待门槛，但总加载 13.39 s，已弃用。这里记录单次观察值，不能推广为所有机器的上限或游戏帧率。

## 回归和缓存

- `tools.dev check`：861 项 Python（9 项条件跳过）、237 项 JavaScript、25 个隐藏原生检查入口及 Ruff 通过。需真实 EXE 的条件检查单独记录，不能把跳过写成已验收。
- 新增错误路径验证：错误文件头、损坏节点、截断、读取时增长、I/O 异常均关闭句柄并保留旧模型；完整验证后才发布新模型。
- 在每个构造检查点重入生产文本回调，仍使用完整旧模型；构造抛错不替换旧模型；提交后使用新模型，后续渲染不执行加载检查点。
- 索引格式、生成规则、语言配对、原生合同及依赖版本未改。解析与映射指纹不含本次改动的加载脚本，已有有效缓存可复用。旧 1.0.4 的模型和 wire 用于本轮性能回放。
- 保留 [1.0.4 文本关联审计](dialogue-coverage-1.0.4.md) 的结果和缺项边界：114 个原始动态调用已有路由，官方日文仍缺 8 条完整对白变体。
- 完整模型解码逐字段摘要一致：205,266 个直接配对和 71,349 个段落桶均保留。加载后 90 秒自然分配回放完成 184,672 次回调，最长观察等待 53.049 ms，通过原 100 ms 门槛；这次运行末段与本地打包重叠，只作门槛检查，不作隔离性能比较。
- 本地候选复用已验证的 1.0.4 原生运行依赖和未改动的启动器，应用为 1.1.0 当前源码。无系统 Python、Unicode 路径、单实例、重载、模拟下一版更新、中断恢复和加载 DLL 时更新均通过；启动观察值 1.554 s。正式发布仍必须使用 GitHub 构建的成品。

复现加载期间等待：

```powershell
python -X utf8 tests/profile_native_model.py --wire <完整模型.wire.bin> --during-load --seconds 10 --output <收据.json>
```

不加 `--during-load` 时仍测加载后的正常分配与回调等待。所有测试只附加其自行创建的隐藏宿主，不启动、附加或修改真实游戏；真实状态来自用户已启动的正式后端日志。新原生 revision 必须随新游戏进程加载，不热替换现有游戏钩子。

本地原始收据保存在 `generated/model-load-*.json`、`generated/check-1.1.0.log` 及 `generated/live-1.0.4-connected-20261031.json`。原始游戏正文、个人路径、用户截图和凭据不随源码或发行包分发。正式成品、升级回退和分发结果待追加；当前不宣称候选实机显示已验收。
