# 1.0.3 全量文本关联排查

本页是本轮任务的当前状态入口。反馈版本未知，反馈用户表示没有安装语音或剧本 Mod。修复、原始资源审计、最终代码回归和性能对照已通过，正在构建并核验发行包；新版本尚未发布，新候选尚无玩家实机验收。

本轮按当前明确的自主修复、测试及发布授权推进。历史候选的验收不算作本候选的实机证据。原工作区的无关改动保持隔离；没有已绑定且可用的 Planban 工具，状态维护在本页。

## 修复范围

- 有限控制串证明器原先只支持一个局部变量及部分条件操作，并把辅助调用参数间的调试行标记当成未知操作。48 个合法中文动态对白调用因此未取得完整身份。现在检查有界区域中的所有可达分支；允许多个受控局部变量、纯条件运算、分页及表情控制。未知输出、可见动态替换、引用逃逸、未知写入、外部进入和预算超限继续拒绝。
- 同正文的多个表情变体曾因去掉表情头而互相冲突。现在用实际观察到的原始控制串 token 选择对应完整变体；运行时表情头改变不再丢失原调用身份。
- 物品消息的可选尾参数是 `global_work` / `set_global_work` 索引，旧限制 0–3 错误排除了两个索引为 6 的物品交付调用。现在保留静态非负 SCP 整数域，不接受变量或表达式。
- 已证明的 opcode-17 物品整句构造扩展到普通对白和字幕，补入两个调用。数量、嵌套调用和未知操作仍不纳入此合同。
- 39 个静态物品整句原先可能被函数内片段词库抢先处理。生产回调回放在其中 6 个物理调用复现了副文不完整。现在以脚本摘要、函数、实际 PC、完整原始参数及整句模式选择专属配对。仅在编译期建立索引，运行时直接查表；没有新增游戏内扫描或钩子。
- 部分外语旧日志含不完整原生注音标记，导致完整官方候选已选中却不生成副文。修复只授予该条完整旧日志候选权限，不删除标记、不补造文字，不将身份权限扩散给普通文本、说话人片段或全局词库。旧日志的既有候选选择仍单独标为 fallback。

SCP 指令与 [Ingert 读写实现](https://github.com/Aureole-Suite/Ingert/blob/main/ingert/src/scp/io/code.rs)、[参数实现](https://github.com/Aureole-Suite/Ingert/blob/main/ingert/src/scp/io/function.rs) 核对。原生构造器和嵌套动作调用另做了只读反汇编检查；没有向现有游戏注入诊断代码。

每语另外保留 367 个未知表段。初筛包含语音/开发注释、数组别名、动画名及未确认可达性的日文卡牌文本；未知段数量不等于漏译数量，没有把它们全部判为非显示文本。未观察的原生显示路径也不在离线覆盖保证内。

## 验证与性能

最终代码 `tools.dev check` 通过：844 项 Python 测试（9 项条件跳过）、232 项 JavaScript 测试、25 个自建隐藏原生进程检查，以及 Ruff 静态/格式检查。测试不启动或连接用户游戏。发行包另做精确源码及实际依赖检查。

1.0.2 对照来自正式 CI 包，同机顺序测量：

| 测量 | 正式 1.0.2 | 1.0.3 最终代码 |
|---|---:|---:|
| 首次准备进程时长 | 170.27 秒 | 172.26 秒 |
| 首次准备峰值私有内存 | 1,855.00 MiB | 1,860.83 MiB |
| 暖缓存进程时长 | 3.23 秒 | 3.22 秒 |

| 暖日志查询及最终渲染，每项中位耗时 | 0.636 微秒 | 0.629 微秒 |

进程时长包含固定 2 秒观察期；查询使用相同的 1,024 条来源、20 轮缓存命中测量。首次准备约增加 1.2%，没有观察到明显退化；单次冷测和 Node 缓存测量不代表游戏帧率、所有查询情形或整段游玩内存表现。

开发环境曾误用未修补的 Frida 17.18.0，40 万回调残留检查失败。隔离安装并核对正式构建所需的 `17.18.0+sora.1` 后，净残留 6 KiB，检查通过。没有修改共享开发环境，也没有放宽原检查门槛。最终包将再次核验实际携带的依赖。

## 重复检查

先用本机合法安装的游戏资源构建完整目录及所选主副语言模型，然后执行：

```powershell
python -m tools.audit_resource_inventory --game <game> --catalog <cache>/catalog.json --output <evidence>/resource-inventory.json
python -m tools.audit_dynamic_coverage --inventory <evidence>/resource-inventory.json --catalog <cache>/catalog.json --output <evidence>/dynamic-coverage.json
python -m tools.audit_history_dialogue_coverage --help
python tests/check_control_dialogue_resources.py --game-dir <game> --catalog-dir <cache> --evidence-dir <evidence>
python tests/check_notification_omissions.py --game-dir <game> --targets ja --existing-catalog-dir <cache> --model-path ja=<model.json> --all-producers --output <evidence>/notifications.json
python -m tools.dev check
```

资源审计从原始 PAC 建立分母，再与目录和生产者联结；动态审计会检查目录摘要一致性，输出 `all_classified: false` 时不得作为完整覆盖通过。历史日志审计按完整候选检查，不把短片段新增到全局字典。

详细证据保存在维护者本地 `generated/`；最终结果使用 `generated/release-1.0.3/`，早期失败及中间结果保留便于红绿对照。PAC 派生正文、完整词库和用户截图不随仓库或发行包分发。
