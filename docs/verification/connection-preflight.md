# 连接失败：书籍钩子安装早于入口校验

## 现场与根因

2026-10-04，用户更新到 0.3.34 后，新游戏进程首次连接报 `Native runtime code changed at book_count`，后端退出。

生产 agent 在校验入口指令之前调用 `createNativeBooks` 安装了书籍钩子。随后 SHA-256 provider 的 Windows CNG 调用提交了 Frida 改写，校验读到本工具刚写入的跳转，把自己的初始化当成外部修改。此问题来自 0.3.33 的书籍接入；0.3.34 沿用了这个错误顺序。

原书籍检查独立调用适配器，原主 agent 的 Node 夹具未装入书籍适配器，两边都无法覆盖这个组合错误。此前的自动检查通过不能证明首次连接成功。

## 修复与回归

- 将全部入口校验移到 agent 取得模块基址后、任何原生适配器构造及原生调用之前。
- 错误提示改为“代码与可执行文件不同、安装钩子前拒绝连接”，不再未经确认指责其他探针。
- 扩展 `tests/check_native_books.py`：直接提取生产 agent 的启动前段，在自建隐藏进程中运行真实书籍适配器、Frida 钩子和 CNG 调用。
- 修改前干净宿主准确复现 `book_count` 失败；修改后书籍适配器正常创建，钩子实际写入。
- 故意改变最后一个入口的负例会在任何适配器／CNG 初始化前失败，且没有新增钩子；没有通过跳过校验来修复。
- 该脚本原本就在 `tools.dev check` 必跑清单中，因此此回归会阻止 GitHub 正式发布。CI 没有游戏资源时仍执行启动组合检查；本机另执行磁盘 EXE 的实际书籍查询指令。
- 完整 `tools.dev check` 通过：506 项 Python 检查（5 项环境相关跳过）、167 项 JavaScript 检查，以及 Windows 隐藏原生宿主检查。启动正反例和实际书籍查询均已执行。

当前游戏没有试装、卸载或叠加诊断钩子。修复后完整游戏连接和提示框视觉效果仍与隐藏宿主证据分开验收。
