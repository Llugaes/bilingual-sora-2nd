# Bug #5：日志仅最后一句显示双语

状态：已定位并修改代码；回调回归与原生分支验证通过，新游戏进程实机验收待执行，不能以词库命中宣称实机完成。

## 现场证据

2026-09-28，PID 5088。`diagnostic-134-runtime-log-open.json` 来自驻留工具已有的只读 snapshot；采集后恢复原配置。`diagnostic-134-story-log-open.json` 由外部 `ReadProcessMemory` 采集，共 785 个 Text 控件，无读取错误。

连续正文与保存身份发生错位：

| 日志正文 | 错绑身份的正文 | 错绑调用 |
| --- | --- | --- |
| 我先回谈话室，等那孩子回来吧。 | 要是找到了，就把人带过来吧。 | EV_03_12_00 / 418 |
| 要是找到了，就把人带过来吧。 | 嗯，我知道了。 | EV_03_12_00 / 421 |
| 嗯，我知道了。 | 好～我们这就开始把逃跑的小猫咪找出来吧！ | EV_03_12_00 / 462 |

正常 builder 捕获到了身份，但登记到错误日志槽位；`withIdentity == commits` 不能证明身份归属正确。精确解析器拒绝正文与身份不一致的行，因而产生“只有最新一句成功”的现象。

## 根因与改动

游戏 writer `0x43DFB0` 有两条复制路径。首次写入时 R8 对应实际槽位；追加路径 `0x43E214..0x43E2AF` 写下一槽（含 1599→0 环回），R8 仍指向前一槽。旧公共出口 `0x43E2DF` 错用 R8 登记，覆盖了前一条的 sidecar。

现在分别在 `0x43E209`、`0x43E2A9` 读取实际复制游标 RCX，减去 `0x180` 得到已写完的记录。身份指向实际目的槽，不取上一槽。此时 `0x188` 字节 payload 已完成，剩余尾部状态位不属于 `logStamp`。整段拼接还需与捕获身份的 source 相等，不能把错误身份交给严格解析。

这不是给句子加白名单，也不是改为按文本替代对话 ID。ID 仍来自游戏原始脚本、函数和物理调用；控件地址只用于跟踪生命周期。

## 验证

`tests/test_native_agent.js` 新增连续三个不同正文的正常显示→写日志→读取→隐藏测量→双语→重开检查，覆盖 0/1/2 与 1598/1599/0。旧生产脚本回放为红：第一句保留中文；修正后全套 145 项 JS 检查通过。证据：`diagnostic-134-log-red.txt`、`diagnostic-134-js-tests.txt`。

旧回放只模拟“R8 永远是目的槽”，且许多用例使用同一原文，未覆盖机器码追加分支；这是此前回归没有发现问题的原因。

`tests/check_native_log_commit.py --exe <sora_2nd.exe>` 在自建隐藏进程执行磁盘 EXE 的两条完整复制分支。空槽、追加 5→6、环回 1599→0 均由 RCX 正确取得目的记录；后两项证实旧 R8 指向前槽。三项均验证提交点的 `0x188` payload 已写完、尾部 flags 仍未写入。`diagnostic-134-native-log-commit.json` 保存分支摘要、执行结果和 EXE 摘要；未启动或附加游戏。

## 多段正文与姓名复核

追加显示路径另有一处槽位错误：`0x35f935` 的 RBX 是相对段数，`0x35f948` 的 RAX 才是实际
环形槽位。`0x35f95d` 与隐藏测量路径 `0x36240b` 均把真实正文指针放在 RDX。现在由正文指针
相对 owner 的 `+0x160550`、步长 `0x18c` 推导槽位，并保留边界、owner、epoch、stamp 校验。
不再将相对段数当成绝对记录位置。

姓名 setter 在正文收集完成后调用，必须继承完整 parts 对应的身份。旧实现只取其中一槽，
多段正文无法恢复 ID；现在核对完整正文和姓名后继承，不能把首段身份冒充整句身份。

真实寄存器合同回放在旧实现上复现失败（`diagnostic-138-multipart-red.log`）；修复后覆盖
1599→0 的多段正文、姓名、显示、隐藏测量和错误 marker 拒绝。最终全套 `tools.dev check`
通过 387 项 Python（5 项跳过）、151 项 JS 以及 Windows 隐藏进程检查。
`diagnostic-138-log-native.json` 另保存实际 PE 的追加参数合同与复制分支执行证据。

驻留钩子不得在游玩中替换。当前游戏仍运行旧钩子；候选版需要在用户正常退出后、下次启动游戏加载。新进程实机连续对白与日志验收尚未执行。
