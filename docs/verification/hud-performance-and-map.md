# 0.3.24 字体、性能与地图地点检查

2026-09-29。适用 EXE SHA-256：`d8b2911d1576216bdc22d070550e4f531e105de7ed2981885849669f4acf8aaf`。
本页区分原始资源审计、生产代码回放、自建隐藏原生进程和真实游戏画面。没有向用户正在运行的游戏追加或替换钩子。

## 已有 HUD 使用旧图集

新 font face 已发布，但已有标签的 normal material 仍引用旧 image。`SetText` 在字符串相同时直接返回，字符串改变后的测量也不负责换材质。因此只换 face、重测字形不足以覆盖自由移动、战斗及弹窗控件。

磁盘机器码核对：

| 入口／字段 | 契约 |
|---|---|
| `0x588A40` SetText | 不更新标签材质；同文提前返回 |
| `0x588B40`，vtable `0xB184B8` | 标签虚函数 `+0x28`，由构造器调用；获取新材质并更新已有普通字形 primitive 的材质引用 |
| font manager `0xC60ED0` | 标签 `+0x300` 是 face index；越界 index 对应空 image，按原生行为保留 |
| material `+0x30` | image 指针；普通材质在标签 `+0x650` |
| shadow batch / material | 字形 manager `+0x40` / 标签 `+0x658`；刷新释放 shadow batch，但旧 material 字段未清零，适配器立即清零，避免再次释放 |

生产 Update 只在字体代次变化时核对材质，必要时调用上述原生方法；随后走共用重测与重绘，并保留动画显示进度。普通 setter 不能提前把代次标记成已刷新。原字体恢复、新控件、重复 Update 与混合代次的阴影使用同一规则。

`tests/check_native_font_materials.py --exe <game-exe>` 在自建隐藏宿主执行该虚函数的原始机器码，只重定位 globals 和外部调用，由 fixture 提供资源。旧实现复现 `HUD uses old atlas after font publication`；修复后旧图集→新图集、恢复、setter 先发生、新控件和重复刷新通过。最终取得 3 次材质、释放 5 次、删除 2 次 batch，数量符合这些场景。GPU 资源创建和游戏画面没有被此检查验证；首次无字体状态的 HUD、菜单、战斗、弹窗切换仍待新游戏进程实机验收。

## 普通解析被反复送入 JavaScript

用户报告一次卡顿后，现有只读状态显示 `primary` 单语模式的 parse 最大耗时增至 355.33 ms、超过 8 ms 的次数增加 2；resolve 与 setter 最大耗时未增长。`nativeMeasure.slow` 累计 36,228,604 次，两个 fast 分支各 3,131 次，未出现容量回退。该计时包含子回调，不与细项相加，也不等于完整 GPU 帧耗时。

`ruby_context_init` 实际是公共 initializer。既有 JS 回调只处理 `0x587084`（副文测量）、`0x586E80`（正文测量）、`0x58714F`（副文放置）三个返回地址，其他普通调用原本进入 JS 后立即返回。现把这一相同判断移到 C 入口，普通调用及其 leave 不创建 JS invocation；原函数仍原样执行。三个注解入口、溢出回退和既有 native fast 分支不变，没有删文本或跳过原生解析。

`tests/check_native_measure_dispatch.py` 在自建隐藏 Frida 宿主连续执行 12,000 次普通初始化：旧实现 81.847 ms、12,000 对 JS 回调；新实现 2.0162 ms、0 对 JS 回调，原生结果一致。三个注解入口仍触发回调。实际 EXE 的嵌套注解、字号、刷新检查另行通过。

完整本机资源模型的 Frida V8 文本回放（不是游戏帧基准）：

| 模式 | 样本数 | 冷 P95 / 最大值 | 热均值 |
|---|---:|---:|---:|
| 主语言 | 606 | 0.0224 / 13.0337 ms | 0.001160 ms |
| 双语 | 695 | 0.7364 / 8.3256 ms | 0.001062 ms |
| 副语言 | 695 | 0.5231 / 7.3096 ms | 0.000903 ms |

输入包括真实完整详情和明确生成的数值／未知控件样本。此纯文本基准不加载 native 身份对象，不代表 GPU、所有原生 setter 或整帧成本。当前证据证明去掉了高频无效桥接；没有证明所有战斗、开宝箱及双语日志卡顿消失。新驻留代码的实际游玩对照仍待验证。

## 地图地点失联

只读实际控件：地图 marker 已有“神秘森林”的副文，`spot_list/items/.../item_template/spot_name` 仍是裸中文。原资源的 `MapJumpSpotData` 对应日文“ミストヴァルト”，`ViewerMapData` 是“ミストヴァルド”，因此全局匹配保留了真实冲突。

两处 `spot_name` builder（SetText 调用点 `0x3DE01D`、`0x3EB01D`）均先复制表名、删除 LF，再赋值，原表指针已经丢失。新增的 `map_spot` 上下文来自这个已核对的控件家族，内容从整张 `MapJumpSpotData` 名称表编译并采用同样的 LF 处理；不按地名加白名单，不覆盖 viewer 或一般正文，同族真实冲突仍保留。

`tests/check_map_spots.py --game-dir <game-dir> --catalog <catalog.json>`：

- 原始八语 PAC 每语 540 条物理记录，161 个唯一名称；目录缺项 0。
- 64 种语言组合，地点家族最终 JS render 10,304 条，缺译和副文差异均为 0。
- 另用完整全局目录回放中文→日文的 161 个名称，保留 viewer 冲突并验证作用域优先级；总计 10,465 次最终 render 通过。
- 控件 setter 回放覆盖双语、副语言、禁用恢复以及无关控件；真实画面复查需加载新驻留代码。

## UI 与启动语言

界面语言移到“设置和更新”；启用开关在“语言”页首位，主副语言采用两列。关闭的下拉框无论有无焦点，滚轮都不更改选择；展开列表仍可滚动。首次界面语言采用三项列表。

主语言按 EXE 路径、PID、创建时间绑定的游戏会话同步一次，使用后端实际检测语言。重新连接同一游戏不会覆盖用户后续修改；检测期间手动修改也保留。新游戏进程重新同步，副语言和其他设置保持原有偏好。没有把 Steam 安装语言当成实际游戏语言。

中文、英文、日文设置页的布局和文案检查通过。完整本地 `tools.dev check`：451 个 Python 测试（5 个依赖其他本地夹具的测试跳过）、162 个 JS 测试；提供目标 EXE 的全部隐藏原生检查通过。最后的 shadow/index 边界修订再跑对应原生检查通过。发布流水线另负责无游戏环境回归、便携 EXE 和离线安装器验证。

驻留模块更新在下一次正常启动游戏后生效；此边界与首次安装时字体加载免重启是两件事。发布本版不意味着正在运行的旧驻留脚本已替换。
