# 第二轮重构方案（未实施）

前置条件：先完成料理标题字号/位置修复，形成新的本地候选并取得用户实机验收。2026-10-11 用户确认 r2 其余表现通过，同时报告装备说明的“女性／男性／角色专用”未关联；该新缺口单独修复和验收。下列大范围批次暂未实施、不发布；每批都有独立变更和验证结果。

## 跨语言一致性是后续批次的验收条件

“语言”分为游戏的八种自然语言，以及编译器 Python／驻留解析器 JavaScript，两个维度均须验证。装备限定反馈已经证明：单个词条能翻译，不代表同一词条进入完整组合后仍能关联；半角／全角标点的不同也不能靠按语言补丁弥补。

新增同族处理按原始资源身份、完整构造和参数域编译，共用已有的运行时消费者。官方措辞、词序、括号和空格来自对应语言资源，不从中文／英文外形推断其他语言。只要现有模型能表达新构造，就扩展同一份编译数据，不再分别增加 Python／JS 分支；确需改变解释语义时才修改两端并比较完整输出。

每个同族修复应保存原始资源分母、未接受记录及原因，覆盖八种来源语言、八种目标语言和主／副／双语输出。核对完整主文、副文、图标、控制符和锚点，保留未知参数、同文异译和缺项负例。截图与实机验收仍单列，不把资源回放通过宣称为八语实机测试完成。

后续清理按构造族进行，优先检查“资源已收录，但组合角色或边界未声明”的缺口；不把重复维护改成另一套全局关键词或翻译猜测。装备限定作为第一条具体现例，正常页面的既有完整 plan 用差分回放保护。

## 先修正问题归属与测量口径

第一轮主要清理重复准备工作、wire 发布缓冲及拒绝策略双写，尚未统一所有布局度量。真实字形归属、字号和测量原点属于 `native_agent.js`／原生布局路径；Python/JS 的文本 plan 只负责文本、UTF-8 锚点、角色身份与附加层，不能把几何补偿塞进翻译编译器。

本次料理反馈已取得同一控件的双语、原文、恢复双语三个只读快照：字号 18 的标题被生成 `<s15><R>…</R…><s18>`，同字副文约为主文的 1.2 倍，主文下沿低约 8 个布局单位；恢复后 17 个标签与初始双语字形完全一致。当前目标是修正公共度量，覆盖同类小字号控件，而不是料理页面的文本或路径补丁。根因及修复另记，不能据此认定是跨语言双写造成的。

前次 2454.67 MiB 是**完整准备流程期间主编译进程的峰值私有内存**，未合计最多四个脚本解析子进程。下一轮的“整体峰值”必须记录同时点的整个进程树总私有内存；工作集、私有内存和仍存活的对象分别报告。

同时区分完整工具与单项准备任务：完整工具统计 UI、连接后端、字体/模型准备 worker 及其仍存活的解析子进程，按同一采样时点求和后取峰值，不能相加各进程在不同时间的历史最高值。覆盖空缓存启动、字体和模型准备重叠、首次模型上传、切换语言的新旧模型交接，以及关闭工具后的进程回收。

游戏内驻留 V8、索引和字体属于另一块内存，不在上述工具进程树内。后续通过自建宿主测量加载前后及语言交接期间的峰值；实际游戏进程的总内存和固定场景观测另列，不能把游戏自身的全部内存算作工具开销，也不能用宿主差值声称实机精确增量。当前游戏不加诊断钩子，已有缓存容量与清表语义暂不更改。

当前最强的主峰线索：候选采样的最高点在动态目录编译结束后、`_load_model` 开始前。此处 `catalog_build.py` 正把仍在内存中的目录对象变成整份 JSON 字符串，再编码写入。现有阶段事件未细分序列化，故这是有证据的优先调查点，尚非逐项内存分配证明。

## A：测清主峰，并按记录分块发布目录

范围：`tests/profile_preparation_memory.py`、`localization/catalog_build.py:21`、`localization/resources.py:1485`，必要时增加一个专用于目录发布的小函数。

1. 探针增加序列化起止、子进程生命周期和同步进程树采样；采样仍只针对自建准备进程。
2. `json.dumps` 按 entry 或有限批次运行，顺序输出元数据与数组成员，避免整份 327 MB catalog 的 Unicode 字符串与 UTF-8 缓冲同时存在。
3. 保留字段/记录顺序、紧凑分隔符、`ensure_ascii=False`、文件编码、临时文件和原子替换；不减少游戏资源校验。

不直接换成逐碎片的 Python `json.dump`，避免以大量小写入和 Python 编码开销换内存；不建设任意格式的流式框架。

验收：脚本与合并 catalog 逐字节相同；八语言、并行/串行、无效及缺失资源的现有检查通过；补空目录、非 BMP、超大单条、批次边界、写入/replace 失败检查。使用相同资源与配置、新建工具缓存，分别报告 OS 页缓存状态和至少交错多次的时间/峰值。收益实测后填写，不预设节省百分比。

## B：缩短编译对象的持有时间

范围：`localization/model_worker.py:21`、`native_catalog.py:330` 后的身份编译阶段，以及确需处理的 translator 临时反向引用。

- `model, signature, _ = ready_model(...)` 中的 `_` 是强引用，冷路径下让完整 entries 一直活到 wire 发布结束。生产 worker 不需要这些 entries，应在使用完成后结束其生命周期；保留其他调用方确实需要的返回契约。
- 得到 `translator.runtime_model()` 后，后续身份编译主要只需 `pairs`。使用已有 `model['pairs']`，避免继续持有整套 regex、辅助 translator 和中间 producer 列表。
- `details.frame_owner → parent` 形成环，单纯 `del translator` 不保证立即释放。应明确编译阶段的所有权与终止点，处理仅编译期间需要的反向引用；不深复制模型，不把强制 GC 加进所有路径。

验收：模型与 wire 字节不变；worker、热缓存、语言切换合同继续通过；证明进入 wire 时原目录不再被 worker 意外持有，进入身份阶段时旧辅助对象可回收。区分“引用已释放”和“Python allocator 已把内存还给 OS”。这一批主要处理后半程重叠，不能代替 A 对当前最高点的处理。

## C：统一有限规则数据，保留语言适配

适合继续单源维护的内容：

| 内容 | 现有位置 | 处理 |
|---|---|---|
| 整数参数种类、极值和拒绝原因 | `menu_text.py`／`runtime_text.js` 的 effect member 校验 | 一份类型化规则数据，两端各自执行数值转换 |
| 成员/分隔符预算和禁止边界 | 两端 effect list 组合器 | 集中有限常量，不生成整个组合算法 |
| 注音断行 class 集合与禁止相邻组合 | `annotation_breaks.py`／`runtime_text.js` | 扩展现有单源数据，不重复建设已有 Unicode 范围生成器 |
| 拒绝强度表 | `effect_refusal_policy.py` | 第一轮已完成，继续沿用 |

仍用 Python 数据模块作为唯一编辑入口、构建时生成 JS 常量，保持无新增运行时 I/O。同步模型指纹、生成一致性、热更新分组、发行清单、旧更新器兼容。

应保留的不同：Python `int/re` 与 JS `Number/RegExp`，code point 与 UTF-16、最终 UTF-8 偏移转换，以及 JS 的候选索引/缓存。不能将 `\d`、`\s`、锚点机械共用。回归语料包含溢出、非 ASCII 数字、换行、astral 字符及孤立 surrogate；期望来自独立原始语料/旧行为，不由新模型自行生成。

本批目标是降低规则漂移风险，不承诺内存或 FPS 收益。

## D：继续收拢效果组合的决定与历史状态

范围仅为“原子成员 → 效果列表”。第一轮已经有显式原子结果，外层仍依赖有顺序的历史失败表；下一步应显式表达组合决定及必要的有序状态操作，在兼容层按原时点执行。

不同时改 `translate/render/ownerPair/history`、不更换清表策略、不直接宣称 resolver 纯化。优先补足既有 `detail_effect_units` 的 typed slot/authority 合同；若确需新增 wire 模型字段，单列版本和旧 resident 兼容检查，不引入并列的万能 IR。

验收继续包含：历史拒绝后成功、合色递归、frame-owner 否决、owned units 不重算、分片短路、19,999/20,000 清表边界；两端完整返回、plan、调用顺序及有序失败表摘要相同。再接原资源 oracle、全模型三模式回放和包内 V8。

## 公共布局实现应承担什么

统一的目标是：给定原始字号、当前主/副语言角色、原生注音/绝对字号语义和控件原点，计算一致的度量与锚点；页面只提供已验证的布局上下文。字体、图标、普通附注和原生 R 子注音的底层操作不同，不能为了“一份函数”把这些差异抹平。

C 快路径和 JS 路径若因性能保留，必须共用同一度量合同和真实场景回归，不能各自决定基准。当前排版修复先建立这条最小公共职责，再据证据决定是否需要进一步合并；不预先改变已经正常的正文/大标题和多行排版。

## 执行顺序与暂停条件

料理修复及实机验收 → A → 测清新的最高点 → B → C → D。A/B/C 可以各自产生可验收本地候选；D 仅在原子结果边界稳定后进入。

任何可见文本、原生控制、图标、角色身份、字形锚点或拒绝行为发生非预期差异，先停止该批并核查，不通过改旧期望放行。回放一致不等于实机验收，正式发布继续等待确切候选的用户确认。

延期：通用规则虚拟机、Python→JS 转译器、预计算全部可能输入、常驻跨进程大缓存、八语言共享 AST 和多进程流水线重写。先消除已证的临时副本与生命周期重叠，再决定是否值得扩大范围。
