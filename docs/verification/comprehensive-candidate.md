## 缓存证据与限制

共享八语目录原本已缓存；重复构建的主要成本在脚本解析、运行身份与组合映射。整树缓存原型性能失败，约 893 MB，首次／对调约 84／103 秒；失败证据留在 `generated/comprehensive-1.0.0/cache-performance-final.json`，未用于候选。

当前缓存投影保留 marker-bearing 函数的**全部 called 描述、顺序和参数**，包括未知调用和动态参数；分支事实仍使姓名关联拒绝。其余函数不能产生原编译器接纳的日志 marker。投影不用于控制流／对白对齐。缓存不保存跨语言配对决定，原串和当前源资源仍读取、核对。

`cache-performance-history.json` 的同机会话单次样本：关闭缓存 67.767 秒；首次缓存 87.279 秒；对调 47.171 秒（2,666 命中、零新解析）；游戏语言切换 43.096 秒（八语日志事实复用，新源身份清单仍构建）；英文配置 44.194 秒；完整模型热读 1.489 秒。首建增加写入成本，新组合仍有组合映射、身份关联、日志上下文及序列化成本，不承诺零重建。测量期间存在本地回归负载，不作为严格隔离的性能排名。

当前事实缓存共有 4,659 文件、178,030,664 bytes。资源变化按原目录的 PAC 大小／mtime 和内容身份失效；解析／身份规则的代码摘要变化失效。单元回归覆盖语言隔离、内容变化、代码变化、损坏校验、动态参数、分支拒绝和权限拒绝不重建。权限限制没有被视为普通缓存 miss。

投影与原完整解析模型比较五份配置／基线通过。最初跨进程逐数组比较失败，原因是 Python hash seed 导致数字规则列表插入顺序不同。只归一化经生产解析器确认无顺序语义的 `numeric`、`raw_numeric`、`detail_numeric` 及 blocked membership 列表，保留重复数；主副对、调用、参数和其他数组仍严格有序比较。证据为 `projection-equivalence.json`；同进程冷缓存与无缓存完整模型另有严格逐字段相等断言。

候选随包 Python 热读四份完整模型 1.39–1.71 秒，已准备 wire 的核对／复用约 0.08 秒；首次 wire 构建约 9 秒。随包 Frida V8 wire 装载样本 0.27–1.68 秒，身份查找／渲染／断言的批量 RPC 0.25–0.33 秒。这些包含通信及测试开销，不是每帧延迟，也不包含游戏现场 VM 识别、字形测量或绘制成本。
