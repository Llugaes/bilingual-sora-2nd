# 第四类：高频同文对白

状态：旧日志的官方候选兜底已实现并回放；正常新对白按真实调用身份保存，另见 [bug #5](log-record-identity.md)。实机新候选待验证。

## 数据与用户确认的边界

原生日志保存姓名文本、正文文本及消息 marker，并非每条都有唯一对话 ID。已采集的“这样啊……”“谢、谢谢。”“哦～是这样啊。”等记录 marker 为 0。相同人物、相同正文在多个真实调用中可有不同译文。

用户在本次会话明确允许：确无身份的旧日志可显示与原场景不完全一致的官方译文；正常对话必须保留准确的游戏对话调用身份。

## 改动

保留精确索引的歧义状态，另编译日志专用候选索引。实际调用 ID 优先，其次原生 marker 的唯一恢复；无身份时先找同说话人的完整官方候选，再找完整正文候选。选择按规范化配对稳定排序，不依赖目录扫描顺序。缺语言片段不再清空已有完整候选，只有不完整资源时仍不生成译文。

候选查找不创建对话 ID，不进入普通菜单或正常剧情的解析路径；已有 ID 的缺项不能借用另一条对白。查询使用预编译字典，渲染时不扫描全文目录。

## 验证

完整模型回放 `diagnostic-134-history-live.json` 中槽位 1295、1459、1471、1477、1510、1528、1587，覆盖七条截图相关实际原串及其表情头/正文控制，ja/en 均产生完整副文。结果保存在 `diagnostic-134-captured-replay.json`；候选结果明确标为 fallback，不能算“恢复了原场景 ID”。

新增回归验证同人物异译、只有不完整资源、目录重排稳定性；原生回调回归验证旧记录显示与隐藏测量、精确 marker 优先、普通 setter 不继承旧日志候选。正常连续对白写入错槽的故障单独修复，不能由候选兜底代替。
