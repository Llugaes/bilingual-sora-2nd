# 退出工具与重新连接

基线：0.3.15 之后的开发分支，包含热缓存读取修复。本改动纳入 0.3.16 发布，实机验收边界见下文。

> 0.3.17 补充：0.3.16 发布前的宿主测试未经过完整生产连接入口，漏掉了 eternalize 早于控制通道创建的回归。该测试已修正，首次连接与重连均调用 `NativeLabels.attach`；详见 [连接启动验证](connection-startup.md)。下文旧测试结果不能证明 0.3.16 首次连接成功。

## 行为与根因

旧托盘退出只结束 UI；后端为避免卸载 Frida 跳板导致游戏崩溃，刻意等待游戏结束。
退出图标消失却仍有后台进程，是既有生命周期设计造成的，不是任务管理器刷新延迟。

新实现让游戏持有已经安装的脚本。退出工具先 disable，取消发现、模型和字体准备，
释放控制连接并等待所有工具进程结束；确认完成后再移除托盘。游戏继续运行，
现有 UI Update 恢复原文，隐藏控件在再次显示前恢复。重开工具使用同一驻留模块，
不再次安装钩子；隐藏／收起和界面代码热重载不触发工具退出。

控制端使用带随机令牌的单所有者本机连接；意外丢失所有者也调用生产 disable。
端点按 PID、进程创建时间、EXE 和协议验证。初始化前预留身份，失败时不能把缺失
端点当作再次安装钩子的许可。已经移交游戏的脚本即使初始化失败也可停用并释放后端。
若旧版本连接或未能移交所有权的异常连接仍未安全结束，UI 保留托盘并显示退出失败，
不假报完成，也不强杀游戏。

准备任务使用独立工作器；Windows Job Object 同时约束工作器与其后代。
退出请求独立保存，不改变语言、快捷键或用户的 enabled 选择。新打开工具会清除退出
请求，因此“退出后再打开”可恢复原设置。

## 检查结果

- `tools.dev check`：413 项 Python 测试（5 项按平台／场景跳过）、151 项 JS 测试通过，
  包含原有全部隐藏原生宿主检查。
- `test_native_overlay`：离线启动真实 UI 子进程，第二次启动激活同一实例；发送与托盘
  同一路径的退出命令后，进程返回 0，单实例服务关闭。不是用 terminate 代替被测退出。
- `test_tool_shutdown`：退出不改用户配置；后端未结束时不得报完成；取消真实准备工作器后，
  工作器和它启动的后代进程均已结束。
- `test_native`：退出前取消不附加游戏；disable ACK 丢失仍关闭控制端；端点初始化失败时
  保留游戏持有的脚本、释放后端，不调用 script.unload。
- `test_agent_control`：PID 复用忽略过期端点；当前游戏端点不可达／协议不兼容时拒绝重复安装。
- `check_native_control.py`：仅使用自建隐藏原生宿主，加载生产控制端及生产 disable，
  安装一个实际 Interceptor。四个独立控制进程交替正常退出与 `os._exit(0)`，每轮宿主
  继续运行、拦截效果由 2 恢复为 1，后续重连可重新启用。错误令牌被拒绝。
- 完整 239,507,427 字节模型经新控制端、生产 packed 解码器和正式解析器完成三轮加载，
  保留 204,339 个配对及存档姓名翻译。三轮总耗时 5.388／5.339／5.256 秒，其中模型
  读取 1.355／1.330／1.328 秒，与此前同机基准接近。该数字不是用户电脑的游戏启动保证。

证据保存在 `generated/diagnostic-142-check.log` 和 `generated/diagnostic-142-transport.log`。
没有启动、重启、附加实际游戏或更改用户设置；隐藏宿主不能代替实际游戏的恢复画面验收。

## 交付边界

开发候选需在下一次正常启动游戏时加载新的驻留代码。已注入旧代码的游戏无法通过 UI
热重载获得新的脚本所有权；旧连接仍须随游戏正常退出一次。实际游戏中的退出恢复画面、
继续游玩、重开工具，以及新电脑的耗时，均保留为实机待验证；0.3.16 正式发布由标签流水线验证和生成安装包。

## 0.3.22：已结束进程被误认存活

现场后端锁已经释放，后端也不在系统活动进程列表中；但 UI 保留的 `Popen` 句柄让 `OpenProcess` 与 `GetProcessTimes` 仍成功。旧 `backend_alive` 仅比较创建时间，于是退出一直超时。退出请求保持为真、连接器已停止，导致重连也不能恢复。

`process_identity` 现在在同一个带 SYNCHRONIZE 权限的句柄上用零等待检查进程结束信号，再读取创建时间。它仍防止 PID 复用，也不受进程退出码恰好为 259 的影响。退出循环每次都会收集子进程结束状态。

新增检查先在旧实现中复现失败：创建真实后端替身、保留父进程句柄、正常退出替身，旧 `backend_alive` 仍为真。修复后退出成功；未结束进程仍拒绝误报成功。全量检查 448 项 Python（5 项跳过）、161 项 JS 及可运行的隐藏原生宿主检查通过。

发行包为 CPython 宿主添加 UI、Backend、Worker 名称和 Windows 版本资源描述；保留原入口点和代码节，不引入第二层常驻启动器。实际便携包验证无系统 Python、中文及空格路径、依赖加载、UI 更新交接、单实例与退出。后端及准备任务统一选择命名宿主，准备工作器的子进程继承同一宿主。安装器也检测新名称的占用。

这次没有修改游戏驻留钩子。原生字体、HUD 及战斗卡顿不属于该退出修复的验证结论。
