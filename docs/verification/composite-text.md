# 组合词条检查（0.3.19）

## 根因与修复

公共解析器此前仅识别行首中点项目符号，没有识别词条之间的 `·`、`・`、`･`。单条状态已入库，但「冻结·即死」等组合不满足整句配对，也没有进入拆分路径。

另两条同类路径已一起处理：字符串参数内的组合词条沿用相同边界；已知标签列表优先于宽泛的 `%s` 模板，防止模板吞入前面的成员。换行、括号等外层边界先处理，完整资源和已证明的数字构造仍优先于中点拆分。未知片段、数字、图标及原生分隔符保留；真实对白冲突仍由调用身份解决。

实现不枚举组合，也不限制两个或三个成员。列表匹配只访问既有精确索引，沿用现有渲染缓存，不增加词库的排列数量。Python 与游戏使用的 JavaScript 规则同步。

## 检查结果与边界

- 截图四组输入经完整生产模型及正式 JavaScript `translate` → `render` 回放，均产生副文：冻结／即死、中毒／炎伤、睡眠／延迟、冻结／石化／延迟。
- `test_composite_text.py` 覆盖两、三、四、五、六、32 成员，中点三种字形及斜线两种字形、颜色、括号、换行、未知成员、数字和图标。单独验证字符串参数、贪婪模板及完整译文优先级。修复前原用例失败，修复后通过。
- `check_composite_texts.py` 从原始目录的状态、效果、条件、范围四族取分母。八种来源语言使用完整表目录；简中→简中/日文、简中/英文、英文/日文另外使用完整生产模型，保留跨领域冲突。33,370 个有序双成员组合、43,670 个多成员组合全部通过。多成员覆盖不同位置、正反顺序及整族长度，不声称穷举无限排列。
- 12,365 次已有复合资源检查同时保留拒绝项。缺语言、参数模板、已是复合短语的字段不冒充独立原子；同文异译、详情上下文可解、显示宽度差异单独列出，不算成组合成功。例如地点名称在地图与地点表有不同日文，“７·７·７”长短标题也不同，不能随意选一条全局译文。
- 完整状态/效果审计 `check_status_omissions.py` 通过已知输入检查；原报告中的未证明参数合同继续保留，不宣称已覆盖全部游戏画面。
- `check_runtime_text_engine.py` 在自建隐藏宿主的 Frida V8 执行真实生产解析器，新增四成员最终注音检查。不附加游戏。

组合审计各批约 0.3–2.5 秒，包含数千输入的首次翻译与最终副文检查；这不是游戏帧率或控件加载时间。当前游戏只读采集未取得截图对应控件，实机画面仍待使用新版验证。

## 重跑

```powershell
python -m unittest tests.test_composite_text
python tests/check_status_omissions.py --game-dir <game> --output generated/status-check.json
python tests/check_composite_texts.py --status-audit generated/status-check.json --output generated/composite-check.json
python -m tools.dev check
```

报告保存在本地 `generated/`，包含每个未准入字段、未知/歧义原子、原始复合记录差异及失败见证，不随发行包发布游戏文本。
