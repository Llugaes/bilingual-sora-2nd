# r7 后续内存优化验证

后续状态：用户验收 r8 并授权发版后，已完成 [1.0.2 正式包与双源发布核对](release-1.0.2.md)。以下“本地候选／未发布”保留为测量当时的状态。

2026-10-11；本地候选阶段，不发布。基线是用户验收的 r7（`be43772562e41bd38eeee59be7a6cab9003edd7a`），游戏 Steam PC 1.04 / CAB62，16 个逻辑 CPU。以下 CPU 100% 表示整机逻辑处理器总量。

## 第一批：双语持续增长是依赖层泄漏

固定菜单 r7 的 359.74 秒观测新增 59.92 MiB，约 9.93 MiB/min；关闭双语的 95 秒对照没有增长。原生测量慢路径每次调用两个 NativeCallback，95.54 秒内增加 45,204 次慢路径，预测泄漏 15.28 MiB，与实测 15.77 MiB 接近。

独立隐藏主机无需游戏或词库即可复现：17.18.0 / V8 的普通 NativeCallback 预热后再调用 30 万次，即使主动 GC，仍残留 53,177,248 bytes。根因是弱回调接管 CPU context 清理后，调用者提前删除弱句柄，清理回调失效。删除这一次提前 `delete` 后，同一检查残留 7,168 bytes。产品不强制 GC、不增加回收定时器，业务原生钩子和 r7 排版代码不变。

源码、单行补丁、上游提交与构建方式见 [固定依赖](../../vendor/frida/README.md)。基于 Interceptor.replace 的替代桥接曾在原生 listener 嵌套路径丢回调，已由原生回归否决并全部撤销。

私有诊断候选仅额外向已有状态报告加入对象数量与 `Frida.heapSize`；不增加游戏钩子。新游戏进程固定道具菜单采样 599.95 秒：

| 指标 | 结果 |
|---|---:|
| 游戏 Private Bytes 净增 | 0.55 MiB |
| Frida 原生堆净增 | 0.51 MiB |
| nativeMeasure 慢路径增量 | 285,729 次 |
| 标签 / layout / lanes | 300 / 192 / 77，全程不变 |
| 工具 UI + Backend 私有内存均值 | 192.00 MiB |
| 工具 UI + Backend CPU 均值 | 0.392% |

采样前后只读字形检查各 114 次、无错误：72 个字形，框 1300×130，anchor 8，局部纵界 `[12.35978889465332,115.15625]`、投影纵界 `[926.6,1029.4]` 保持一致。此证据覆盖固定菜单及独立回调释放，不能推广成所有游戏场景都不存在其他泄漏或 FPS 提升。

完整原生回归已在初次构建上通过：Python 819 项、9 跳过；Node 228 项；隐藏原生主机检查通过。初次实机扩展 SHA-256 `11b0196b9c383755cedb64583458a5b0f6f0ecac0f3048c7b5ffc5a8f764709e`，正式配方重构建 SHA-256 `8b71179649d5fa70c41a120acd10e0f813eecafd680ba4be651e744505d0eb5a`。两者身份分别保留；最终扩展另经下文完整回归及实机验证。

## 第二批：准备峰值基线

隔离缓存、同机 r7 完整生产 prepare_request 与所有后代进程，首次准备 206.57 秒，Private Bytes 峰值 2450.51 MiB；已有模型再次准备 2.73 秒、峰值 1096.18 MiB。冷测仅清空应用缓存，没有清 OS 文件缓存。最高点位于合并目录 JSON 写入，四个解析子进程的并行峰值为 1466.53 MiB。

合并目录 984,659 条，UTF-8 文件 326,964,644 bytes；一次性 JSON 字符串占 582,693,478 bytes，写入时还产生编码副本。目录分批写入后，峰值转移到模型写入，仍有 2420.30 MiB；继续对模型采用共同写入函数，并释放临时编译对象、复用完整校验的热缓存，降至 2031.42 MiB。最后直接构建 indexed wire、避免完整中间节点表，并解除递归打包闭包的引用环。闭包滞留能被 GC 回收，与前述 Frida 原生泄漏区分；修复通过对象生命周期回归验证，不调用强制 GC。

## 最终成品结果

本地候选 `1.0.1-dev1-r8`，源码 `66cdff85c19f40bd7b70912aaa6e20cf1a160812`，运行时 `140e00f01d86972b`。ZIP 大小 77,740,222 bytes，SHA-256 `3477fb40de3cb1a79f4deac3dc731c54c913db18d07d537a6af5c1e061cb1eeb`。没有推送或发布。

使用成品内置 Python 3.14.7、空应用缓存及真实完整资源，统计准备进程与所有后代进程的 Private Bytes：

| 指标 | r7 | r8 成品 |
|---|---:|---:|
| 冷准备峰值 | 2450.51 MiB | 1858.29 MiB（降低 24.2%） |
| 热准备峰值 | 1096.18 MiB | 20.96 MiB（降低 98.1%） |
| 冷准备返回后、worker 退出前 | 1857.91 MiB | 711.76 MiB |
| 准备调用耗时，冷 / 热 | 206.57 / 2.73 秒 | 212.05 / 1.03 秒 |

采样脚本额外等候 worker 2 秒后退出；该等候不计入上表调用耗时。冷测最多六个进程，热测两个，结束后均无准备进程残留。单次冷耗时略增，不声称冷准备加速。这不是整套 UI＋字体＋游戏的开机峰值，也不是游戏 FPS 测量。

最终成品正常连接新游戏并读回独立测试档，继续游戏弹窗、人物名字和任务提示双语正常。180 秒采样前 40 秒有页面切换，游戏 Private Bytes 增加不能当作固定场景泄漏；稳定尾段 119.69 秒、240 样本均为前台双语：标签固定 217，慢路径新增 56,910 次，游戏 Private Bytes 净变化 **−2.19 MiB**，没有此前线性增长。工具 UI＋Backend 私有内存平均 **189.86 MiB**，CPU 平均 **0.414% 整机**。未改动 r7 的游戏端 JS 文件，672 个成品管理文件摘要复核通过。
