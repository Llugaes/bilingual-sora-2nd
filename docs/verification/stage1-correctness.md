## 主动语音

独立分母来自八份原始 table PAC 的 ActiveVoiceTableData 记录：每语 2,481 行、1,016 个会话。会话 541 第一行的 `+80` 数组在部分语种为 1333、另一些为 1334，导致整个有序会话的身份签名分裂。

本机 EXE 的 ActiveVoice manager 将 `+80/+88` 作为已播放标记数组及数量，先检查标记再写回；`+48/+56`、`+64/+72` 为另外的条件数组，`+96` 语音资源和 `+112` 正文保持独立。只有跨语言显示对齐排除已证明的播放标记载荷及数量；原生来源验证仍保留全部实际字段，数组边界仍检查。说话人、会话、条件和语音变化均不得据同文配对。

`tests/check_active_voice_resources.py` 从全部物理行经过正式配对、身份编译、指针重定位验证到 JS render。证据目录 `generated/stage1-correctness-1.0.0/` 中的 `active-voice-manager-continuation.json` 保留机器码，`active-voice-resources.json` 保留 19,848 个来源回放及会话 540/541 的独立身份。准确现场配置为 **游戏简中、工具主日副简中**；该原现场的实际控件原串、key 和驻留链尚待新候选采集确认。

同一检查额外读取 fresh、scope=all 的完整简中来源模型：2,481 行通过，2,267 行走完整目录的直接配对，214 行走真实表指针身份；会话 540/541 分别核对，没有借用另一会话的条目。

## 有限动态控制对白

静态 parser 不再因一个动态参数遗漏可证明的完整输出，但不擦除变量。`control_dialogue.py` 仅允许所有可达赋值都是字面 K 控制的单局部变量；可见替换、未知写入、循环、未初始化、重复元数据及外部控制流进入区域均拒绝。调用 PC 来自唯一完整参数生产者与真实字节码，不能将嵌套调用的执行顺序与 metadata ordinal 直接等同。

八份原始 script PAC 的独立 called-descriptor 分母有 496 个 group-5 含 var 候选；两处同类对白、八语共 16 个物理调用证明通过，480 个保留为拒绝项。每个有限输出保留原控制、物理 called ID、赋值指令和稳定 variant key。运行时同时验证实际 PC、控制参数原值和完整输出；拒绝保留 call ID 和原因，阻止正常对白及其日志进入通用词典回退。

`tests/check_control_dialogue_resources.py` 保留全分母、32 个真实语言输出证明、可见替换负例、两种完整生产模型中的捕获与跨来源重载。`control-dialogue-resources.json` 和 `joshua-control-manifest.json` 是当前证据。没有据截图描述声称现场变量已采集。

## 效果构造与排版

HP Regen 在 name/stat 中对应效果显示名，在另一记录的 turns 中对应构造器参数。完整 FORMAT8 列表只使用已证明的显示角色；全局同文冲突继续隔离，同角色冲突、缺语言和未知成员继续拒绝。

对行数已一致的富文本，保留各硬行的副文所有权，分别关闭／恢复颜色、粗体与字号，原生 R 注音保持原子。重分配只处理实际行数差异，不能因为出现颜色或图标就把效果尾部搬到说明行。详情中的 UI 样式前缀不再成为资源上下文；已知完整说明独立解析，说明换行变化只在说明区重排。

副文分段使用本机 ICU 导出的 Unicode 15.1 Line_Break 属性，保守检查 CJK 行首／行尾标点、词边界、组合字符、Hangul、胶合字符及注音原子。生成器是 `tools/generate_annotation_break_data.py`。这是分段边界检查；字形宽度和自动软换行仍由原生引擎测量，不能据字符容量宣称屏幕像素排版已验收。

回归区分真实资源构造串、合同范围内的数字／组合探针、合成布局负例及实机画面。最终候选需观察效果与说明相邻边界、不同宽度、颜色／图标／控制、注音和 CJK／拉丁混排；本地隐藏宿主与原资源回放不替代用户验收。
